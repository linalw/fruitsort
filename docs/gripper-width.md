# 夹爪开口/夹持力标定，以及"宽度设定点"为什么用不了

> 背景：10 seeds 复核里掉落 2/28，**两次都是"夹到上肩"**。这一轮想用「宽度设定点」
> （`--width-setpoint`）把夹持力收住，结果发现这条路在当前动作语义下**走不通**——
> 下面是实测证据，免得下次再踩。

## 1. 标定：指令 → 开口 / 接触力

`python scripts/calibrate_gripper.py` → `assets/calib/gripper_width.json`（苹果直径 65 mm）：

| 指令 g | 空载开口 | 夹苹果开口 | 指端 Fn |
| --- | --- | --- | --- |
| −1.00 | 0 mm | 0.0 mm | 0.0 N |
| −0.70 | 0 mm | 0.0 mm | 0.0 N |
| −0.40 | 10 mm | 10.1 mm | 0.0 N |
| −0.10 | 25 mm | 25.0 mm | 0.0 N |
| +0.20 | 40 mm | 40.0 mm | 0.0 N |
| **+0.40** | 50 mm | **58.7 mm** | **4.1 N** |
| +0.60 | 60 mm | 60.5 mm | 0.3 N |
| +0.70 | 65 mm | 65.6 mm | 0.3 N |

两条可用的结论：

1. **空载映射就是 `gap ≈ 30 + 50·g`（mm）**，与代码里的经验公式一致；
2. **真正的"夹住"发生在 g≈+0.4**（开口 58.7 mm、4.1 N）；g≥+0.6 只有 0.3 N，几乎没夹住。

> 注：g ≤ +0.2 那几行"夹苹果"开口与空载相同、力为 0 —— 说明静态台架里果实被指面**推走了**
> （下降时张开、到位后再闭，果子会滚）。这几行数据不可用，只取 g ≥ +0.4。

## 2. 宽度设定点：先修掉一个真 bug，然后发现走不通

`--width-setpoint` 原来在 `glogit>0 or phase==2` 时都强制 `grip = (w−0.030)/0.050`。
**搬运段（phase 2）无条件套用**，于是放料时也被覆盖 —— 果子永远放不下来。
实测（seed 60004，2 局）：全闭合 3/4，宽度设定点 **0/4**。

修掉这条（只在 `grip < 0` 即"想闭爪"时生效）之后：`delta=6 mm` → **0/4**、`delta=10 mm` → **1/4**。

原因在**动作语义**：苹果要夹到 56–62 mm 的开口，反解出来的 `g` 是 **+0.4 ~ +0.6（正数）**，
而整条执行链（`_grasp_proxy` 的 `prev_grip<0`、`carry_latch`、放料门的开合判断、`closed_steps`）
都把 **正数当"张开"**。所以宽度一设，`grasping` 永远不成立 → 抓不起来。

**结论**：宽度设定点要能用，必须把"开/合"从**符号约定**改成**显式状态**（`self.closed`），
涉及 6–8 处；这不是加个参数能解决的。

## 3. 力上限（`--close-force-th`）：实测无变化

新暴露了 `--close-force-th`（指端力超过它就退到 −0.3）。在**两个掉落的 seed** 上对照：

| seed | 基线 | `--close-force-th 6` |
| --- | --- | --- |
| 60004 | 3/4（1 掉） | 3/4 |
| 60007 | 2/3（1 掉） | 2/3 |

**没有变化** —— 说明"夹到上肩"时指端力并没有明显超限（是小接触面 + 低摩擦，而不是夹太紧）。

## 4. 下一步（有依据的选择）

1. **把开/合改成显式状态**，再试宽度/力设定点（这是唯一能让 `--width-setpoint` 工作的改法）；
2. 或者直接在**夹持点位置**上做文章：上肩夹持说明闭爪点偏高 —— 但 `--close-z-off-map` 已试过
   （−4 mm 更差），需要更大的下探幅度配合搬运限速；
3. 触觉滑移检测（`slip_guard`，runner 里已有、还没接 CLI）在**搬运段**降速也是候选，
   但它只能在"已经滑了"之后补救。

## 5. 按"显式开合状态"重构之后（v1.104）

### 5.1 重构内容

把执行链里 8 处"靠 `grip` 符号判断开/合"的地方改成显式状态 `self.closed`：

| 位置 | 原判据 | 现判据 |
| --- | --- | --- |
| `_grasp_proxy` | `prev_grip < 0` | `prev_closed` |
| 吸盘吸附判据 | `prev_grip < 0` | `prev_closed` |
| 抓取近似判据 | `prev_grip < 0` | `prev_closed` |
| 单侧接触微伺服 | `grip < 0` | `closed` |
| 闭爪前重抓 | `grip < 0` | `closed` |
| 下探目标重置 | `grip < 0` | `closed` |
| 闭爪高度门 | `grip < 0` | `closed` |
| 抓空复位 / `hold_latch` / `stats` | `grip < 0` | `closed` |

闭爪指令由 `_close_cmd(kind)` 统一给出：有宽度设定点就按目标开口反解（**可以为正**），
否则 `-1`（合到底）。这样"开/合"与"指令数值"解耦。

### 5.2 回归：全闭合不受影响

同 3 个 seed（60002/60003/60004）：重构前 10/11，重构后 **10/11**（3/3、3/4、4/4）。14 项测试通过。

### 5.3 宽度设定点：**仍然 0 交付**，但原因换了

扫了 5 组参数（`delta` 2/4/6/10 mm，`contact-force-th` 0.2/2/4 N），全部 **0/4**；基线同 seed 3/3~4/4。

trace 显示两件事：

1. **果实被"弹出"**：目标开口 58–60 mm 对 65 mm 的苹果意味着 5–7 mm 挤压，位置伺服会把果子挤出去
   （标定表里 g≤+0.2 那几行"夹苹果开口=空载开口、Fn=0"就是这个现象）；
2. **即使轻触也会误判"抓住了"**：`ph=2`、`att=False`、`bd` 从 34 cm 一路涨到 58 cm ——
   进入搬运段却没夹住，手臂往料框反方向走。把 `contact-force-th` 抬到 2/4 N 也救不回来。

**结论**：在这个接触模型里，"位置式宽度设定点"不是合适的接口——苹果的可夹窗口太窄
（低于 ~58 mm 就被挤飞，高于 ~60 mm 又没有夹持力）。要真正解决上肩掉落，方向应该是
**力控闭合**（闭合到 Fn≈4 N 就停止）或**更换指面/软指**，而不是位置宽度。
