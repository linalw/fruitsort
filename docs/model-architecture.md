# 模型架构：多视角时序策略（v0.5）

> 目标：把 12 篇论文里被实测有效的机制，落到「单臂 + 动态传送带 + 水果分拣」这一具体任务上。
> 代码：`src/fruitsort/models/vision_policy.py` · 训练：`scripts/train_vision_policy.py`

## 1. 总体结构

```text
                 ┌── overhead RGB (T 帧) ──┐
                 │                         ├─ 共享 CNN（RGB + 帧差 4 通道）→ 128
                 ├── wrist RGB   (T 帧) ───┘
                 │
                 ├── 状态 49 维 (T 帧) ──── MLP → 128
                 │
                 └── 任务/类别 embedding → 128
                                │
                    + 视角类型编码 + 时间位置编码
                                │
                    Transformer ×4 层（因果掩码，8 头）
                                │
                             [CLS]
                          ┌─────┴─────┐
                动作分块头 K=8×4    未来预测头 H=4×24
                (目标位姿+夹爪)      (4 类水果 pos+vel)
```

## 2. 论文 → 模块映射

| 机制 | 来源论文 | 本项目的实现 |
| --- | --- | --- |
| 多视角输入（固定 + 腕部） | StreamPI / FASTER / TEMPO | overhead + `panda_wristcam` 手眼相机，共享 CNN |
| 帧差作为运动线索 | DynamicWAM / Reflex | 图像 4 通道：RGB + \|I_t − I_{t−1}\| |
| 历史 T 帧 + 因果注意力 | StreamPI 原子时间单元 | T=5，时间位置编码，token 级因果掩码 |
| 动作分块（chunk） | ACT / FASTER / DiscreteRTC | K=8，每步重规划取第 0 步 |
| 未来状态预测辅助任务 | AHEAD / DynamicWAM / TrajWAM | 辅助头预测未来 4 步 × 4 类的 pos/vel |
| 任务/语言条件 | NEO / VLA | 类别 embedding（预留文本编码器接口） |
| 预测与抓取解耦 | AHEAD / TrajWAM | 辅助头只做表征学习，抓取仍由动作头输出目标位姿 |
| 延迟感知执行 | LIBERO-Dynamic / FASTER | 训练时随机丢帧（待加），推理每步重规划 |

## 3. 模块细节

### 视觉编码器（共享）

```text
Conv(4→24, k5,s2) → BN → ReLU
Conv(24→48, k3,s2) → BN → ReLU
Conv(48→96, k3,s2) → BN → ReLU
Conv(96→96, k3,s2) → BN → ReLU
AdaptiveAvgPool → 96 维
```

- 输入 **96×96**（overhead 从 640×480 下采样，wrist 原生 128→96）
- 第 4 通道是相邻帧差，零成本运动特征

### 时序 Transformer

| 项 | 值 |
| --- | --- |
| d_model | 96 |
| 层数 / 头数 | **2 / 4** |
| FFN | 384 |
| 历史 | T = 4（20 Hz 下 0.2 s） |
| 序列长度 | 1 + T×(2 视角 + 1 状态) + 1 指令 = 14 |
| 掩码 | 因果；CLS 看全部 |

### 输出头

- **动作头**：`Linear(96 → 32)` → `(K=8, 4)`，目标 = 世界坐标 (x, y, z) + 夹爪
- **未来头**：`Linear(96 → 72)` → `(H=3, 4 类 × 6)`，预测未来 pos/vel（辅助损失权重 0.2）
- **指令**：类别 id ∈ {all, apple, strawberry, banana, pear} → embedding，加到 CLS

## 6.3 达成指标（v0.8）

**四类同场**基准（`scripts/benchmark_sorting.py`，四个水果同时在传送带上，带速 0.08 m/s）：

| 执行形态 | 成功率 | 单件节拍（均值 / P90） |
| --- | --- | --- |
| **模型选择 + 伺服**（teacher，20 episodes） | **19/20 = 95.0%**（CI 76.4–99.1） | **2.82 s / 3.02 s** |
| 模型选择 + 几何执行器（hybrid，40 episodes） | **39/40 = 97.5%**（CI 87.1–99.6） | 3.97 s / 4.21 s |

按类别（hybrid，各 10 次）：苹果 100%、草莓 100%、香蕉 90%、梨 100%。
按类别（teacher，各 5 次）：苹果 100%、草莓 100%、香蕉 80%、梨 100%。

- 节拍口径：水果进入抓取区 → 放置完成（不含传送带上的等待）
- 指令选择：**96/96 = 100%**（四类，`scripts/eval_selection.py`）
- 目标：成功率 ≥85%、单件 ≤7 s —— **两项均达标**

关键修复：
1. 梨改为更圆回转体（h70/r30），并降摩擦 0.8、提高角阻尼 3.0 —— 消除长距离侧滚（梨 4 类场景 40% → 100%）
2. 香蕉/梨放宽触底判定（0.045）—— 下探会顶到带面，不再卡在 DESCEND
3. 抓取后先 1.5 cm/步垂直抬 5 cm 再搬运 —— 避免甩飞

## 6.4 自蒸馏与延迟增强（v0.7）

- **自蒸馏**：用 5/5 的 teacher（模型+伺服）重新采集 24 条示教，访问分布正是纯模型需要的
- **延迟增强**：训练时以 0.2 概率把最后一帧替换为上一帧（模拟 1 帧推理/感知延迟）
- 结果：**纯模型闭环仍然 0/5**，模型+伺服保持 5/5
- 结论：分布漂移不是靠"补数据分布"就能解决，闭环纠偏层是结构性的

**预测驱动伺服的尝试**：把未来预测头接进伺服（AHEAD 思路），但未来头未学会——
预测 0.1 s 后的水果位置平均误差 **0.96 m**（退化为均值），因此不可用。
当前伺服用 `水果位置 + v·0.10`，苹果/草莓 5/5。

## 6.45 标签 bug 与纯策略突破（v0.11）

**根因**：`ScriptedSorter._action` 把 `last_target` 存成了"限速后的 6cm 目标"，
所有示教标签都变成 `目标 ≈ 当前 TCP`，模型因此学成悬停不动点。

修复后（标签 = FSM 真实目标）：

| 策略 | 0.08 m/s，苹果，5 episodes |
| --- | --- |
| 修复前（限速标签） | 0/5 |
| **修复后（raw 标签）** | **2/5 = 40%** |
| 修复后 + 学习式残差（+8cm 预算） | 1/5（噪声内，未改善） |

0.30 m/s 纯策略：0/4（示教只有 0.04–0.08 m/s，速度分布外）。

结论：悬停不动点确实是标签 bug，修复后纯策略能动了；但要到可用成功率还需要
更多示教（当前 33 条）与高速数据，以及残差的正确形态（TCP 相对增量 + 在环 DAgger）。

## 6.46 纯策略 + 吸盘（v0.12 进行中）

用吸盘控制器在 0.15/0.30 m/s 采 100 条成功示教，与 33 条 raw 标签示教混合训练
（`runs/vpolicy-mix`，val 0.10），再用 `eval_policy_suction.py` 评测：
策略输出接近/吸附触发/搬运/释放，吸盘只做附着物理。

| 训练数据 | val loss | 0.30 m/s 闭环 |
| --- | --- | --- |
| raw 33（0.08） | 0.45 | 2/5（苹果，40%） |
| raw + suction 100 | 0.10 | 苹果 2/5；四类 1/16 |
| + DAgger 24（157 条） | 0.33 | **0/16** |
| 仅 suction 100 | **0.064** | **0/16** |

结论：**拟合越好、闭环越差**——这是典型的闭环分布漂移。策略在 0.3 m/s 下无法稳定进入
「距水果 10 cm」的吸附窗口；手写吸盘控制器是 24/24。

尝试过的补救：动作块 open-loop 执行（0/4）、DAgger（更差）、delta 动作（0/5）、
学习残差 8 cm（1/5）。当前 0.41M MLP+2 层 Transformer + ~150 条示教不足以覆盖高速闭环。

## 6.47 相位门控对照（v1.0.1）

在纯策略上加几何相位门控（未抓住前强制接近、禁止切搬运）：

| 配置（0.08 m/s，苹果，5 episodes） | 成功率 |
| --- | --- |
| 纯策略（模型目标+模型夹爪） | 2/5 = 40% |
| 纯策略 + 相位门控 | **0/5** |

门控把模型输出完全覆盖成几何目标，等价于退化成脚本控制器（且没有搬运段逻辑），
因此更差。结论：在当前数据/架构下，纯策略与硬门控都不成立；
要么 500+ 示教 + ACT/DP，要么接受分层执行（模型选意图 + 伺服/执行器）。

## 6.48 大规模示教 + ACT（v1.1 实验）

- 用验收配置采 **367 条成功示教**（0.25 m/s / 30 Hz / 平行夹爪）
- ACT-lite 6.87M 训练 80 epochs：val 0.108，xyz 0.005
- 纯策略 0.25 m/s 苹果：**0/5**
- 轨迹诊断：**ACT 跟踪是好的**（t=30 时 TCP 与苹果重合），但闭爪相位错误
  （t=90 时水果已到 x=0.26，TCP 在 0.32 才闭爪），close_rate 0.53 但时机错
- ACT 运动 + 几何闭爪：**0/5**（目标悬停高度 0.57 vs 果心 0.48，闭爪窗口不满足）

结论：数据量从 33→367、模型 0.41M→6.87M 都没有改变闭环结果；
瓶颈是「接触时刻的相位/时序」，不是拟合或容量。要解决需要相位监督 +
大规模在环 DAgger（每次迭代重新采集数千条），超出单轮会话成本。

## 6.49 真正的失败机制：目标 z 的「分支被平均」（v1.2 诊断）

之前把闭环失败归因于「闭爪相位偏晚」，进一步追到根因：**目标 z 有三个分支被
单峰回归平均掉了**。示教标签（`scripted._action` 的真实目标）在同一状态下是：

| 段 | 目标 z | 触发条件 |
| --- | --- | --- |
| 接近（TRACK） | 果心 + 0.09 | 还没对齐 |
| 下探（DESCEND） | 果心（0.46–0.48） | 已对齐 + 在抓取区 |
| 搬运（CARRY） | 0.60 | 已抓起 |

模型看到的历史里不含「我在哪一段」，于是输出落在中间解（0.50–0.57），
永远不进入 `z <= grasp_z+0.015` 的闭爪窗口；等它闭爪时水果已经过去
（实测：苹果 x=0.26 时 TCP 才在 x=0.32 闭爪）。

相位标签可以从示教动作反推，且与专家闭爪率对齐（apple 搬运段 0.36 + 下探 0.36）：

```
d500-apple      接近 0.28  下探 0.36  搬运 0.36   （闭爪率 0.586）
d500-strawberry 接近 0.46  下探 0.24  搬运 0.30
d500-banana     接近 0.56  下探 0.19  搬运 0.25
d500-pear       接近 0.66  下探 0.22  搬运 0.12
```

对应改动（`--phase`）：
1. 状态追加 3 维 1-hot(接近/下探/搬运)，obs_dim 49→52
2. 新增相位辅助头（3 类 CE，每步监督），推理端用 k=0 的 argmax 作为**下一步输入**
   —— 相位由策略自己预测，不是脚本谓词
3. 进入/退出「搬运」只由真实夹持信号（`is_grasping`）决定，抓空 20 步自动回退，
   消除示教里不存在的「单向门」

## 6.50 DAgger 首轮的两条负结果（v1.2）

1. **只加 DAgger 数据不改善闭环**：`d500(367 条) + dagger-r1b(24 条)` 重训 ACT，
   val 从 0.108 恶化到 1.07，0.25 m/s 四类纯策略 **0/12**（每类 3 episodes）。
2. **DAgger 数据会污染相位头**：同一批数据加 `--phase`，验证集相位 CE 从 0.093
   涨到 1.31（只用 d500 时 4 epoch 就到 0.093）。

原因：r1b 的标签是「学生悬停状态下由几何规则打的标」。学生从未进入抓取窗口，
于是 99% 的帧被标成「接近」，其中 apple 的下探+搬运帧只有 1%。这等于教模型
「永远悬停」。DAgger 只有在学生已经会抓、只需要纠偏时才有增益；学生在抓取前
就停住时，几何重标注会退化成「悬停在远处」。

处置：相位策略只用 d500 的干净示教训练；DAgger 留到学生能进抓取窗口之后再开。

## 6.51 绝对目标位姿 = 轨迹回放（v1.2 trace 证据）

相位条件化训练收敛（val 0.117，相位 CE 0.0165 ≈ 离线 3 类几乎满分），但 0.25 m/s
四类闭环仍 **0/12**。差别在于：模型现在**会进入下探段**（apple 626/900 步），
但从不闭爪、从不进入搬运段。单局 trace：

```
t= 30 tcp=[-0.28 -0.01 0.56] apple=[-0.26 -0.04 0.48]  tgt=[-0.27 -0.01 0.57]  ← 重合
t= 50 tcp=[-0.22  0.01 0.54] apple=[-0.09 -0.04 0.48]  tgt=[-0.24  0.00 0.54]  ← 目标落后 15cm
t= 90 tcp=[-0.06 -0.01 0.48] apple=[ 0.25 -0.04 0.48]  tgt=[-0.04  0.00 0.47]  ← 落后 31cm，此处才闭爪
t=140 tcp=[ 0.13  0.13 0.56] apple=[ 0.45 -0.04 0.48]  tgt=[ 0.12  0.14 0.57]  ← tgt==tcp，机械臂冻结
```

**根因不是相位，也不是容量**：绝对目标位姿让 BC 退化成「按历史回放轨迹」。
示教标签来自一个**闭环伺服**（目标永远比当前 TCP 超前 ≤6cm），模型学到的映射是
「给定这段历史 → 轨迹上的这一点」，既不含也没有学到“误差→修正”。
一旦实际 TCP 落后于水果，模型输出的目标仍然停在与水果接触过的那个点，
误差没有负反馈通路，于是滞后单调增长，最后目标与当前位姿重合（`tgt==tcp`），
手臂彻底停住。

对应处置：改用 **TCP 相对增量**（`--delta-actions`，标签 = 专家目标 − 当前 TCP，
幅度中位数 15cm，执行端裁剪到 6cm 保留方向）。这样模型输出的是反馈量本身，
滞后在每一步被自动修正。

## 6.52 增量模式 + 安全界限：仍 0/12（v1.2 收口）

`--delta-actions --phase` 训练收敛（val 0.169，相位 CE 0.015），单局 trace 显示跟踪
滞后确实变短（`t=20` 时 TCP 已与苹果 xy 重合），但出现两种新失败：

1. **提前闭爪**：水果还在 16 cm 外就闭爪（相位头把「下探」判早了）。
2. **下探锁死**：相位停在「下探」，模型持续输出 6 cm/步的向下增量，压到带面后
   PD 饱和，手臂整体冻结（`dx` 恒定 −0.58，`tgt==tcp`）。

加了两条部署端安全界限后（目标 z 不低于果心 +5 mm；水果被越过 8 cm 时解除下探段）：

| 配置（0.25 m/s，苹果，3 episodes） | 结果 | 闭爪率 | 下探步数 |
| --- | --- | --- | --- |
| 绝对目标 + 相位 | 0/3 | 0.06 | 597–626（锁死） |
| 增量 + 相位（无界限） | 0/3 | 0.07 | 全程锁死 |
| 增量 + 相位 + 安全界限 | **0/3** | 0.12 | 21–39（能退出） |

安全界限把「锁死」变成了「能退出重试」，但抓取仍未发生：模型在水果进入抓取窗口
的那几帧没有闭爪。至此为止，本轮共 4 次训练 / 3 组闭环评测，纯策略在 0.25 m/s
四类合计 **0/21**（每类 3 episodes，另加多组苹果复测）。

**结论**：单峰回归 + 367 条示教无法覆盖「闭爪时刻」这个窄时间窗；数据里的
专家标签是**带历史的 FSM** 输出（同一状态在不同相位下有不同标签），
BC 学到的必然是轨迹回放而非反馈律。要跨过这一步需要状态反馈专家打标
（DAgger with a state-feedback teacher）或 10× 量级的、带恢复动作的示教。

## 6.53 增量标签修正后首次非零（v1.3）

把增量标签从「原始目标差」改成**实际执行位移**（每步裁剪到 ±6cm，chunk 内每步用各自的
TCP）后重训（`runs/act-phase-delta2`，val 0.145，相位 CE 0.0154）：

| 配置（0.25 m/s，苹果，3 episodes） | 结果 | 闭爪率 | 下探步数 | 搬运步数 |
| --- | --- | --- | --- | --- |
| 绝对目标 + 相位 | 0/3 | 0.06 | 597–626 | 0 |
| 增量（原始差） | 0/3 | 0.07 | 锁死 | 0 |
| **增量（执行位移）** | **1/3 = 33%** | 0.05–0.62 | 4–34 | 0 / 0 / 77 |

成功的那一局 `carry=77`：策略自己闭爪、抬起、搬过中点、到框上方、开爪落入——这是
**抓取与搬运第一次全部由策略输出**完成（无脚本执行器）。失败局的特征是几乎不进
「下探」段（descend 4–32 步），说明剩下的瓶颈是相位/闭爪时机的**触发率**，而不是
表达能力。

## 6.54 动作块与前馈超前（v1.3 收口，均无改善）

在 `runs/act-phase-delta2`（苹果 1/3）上试两种部署端改动：

| 配置（0.25 m/s，苹果，3 episodes） | 结果 | 现象 |
| --- | --- | --- |
| 每步重规划（s=1） | 1/3 | descend 4–34 步，迟疑 |

1. **同分布重采**：0.25 m/s 权重在 0.08 下闭爪率 0.00（0/5）——速度变了必须重采。

2. **增量动作标签 = 实际执行位移**（裁剪 ±6cm，chunk 内每步用各自 TCP）。

`--grip-ema 0.6`（夹爪 logit 平滑）、`--carry-latch`（搬运段连续 3 步预测开爪才松手）、

## 6.13 提高控制频率到 60 Hz（v1.10，负结果）

假设：0.20 m/s 的闭爪窗口只有 ±3 帧（30 Hz），把控制频率提到 60 Hz 应变成 ±6 帧。

**顺带修掉一个真 bug**：`ScriptedSorter` 的时间常量（`close_steps=12`、看门狗 500 步、
渐进闭爪 `counter/8`、搬运 90 步看护）是按 30 Hz 设计的；60 Hz 下同样的步数只有一半
真实时间，专家抓不住（草莓 0/50）。改成 `rate = control_freq/30` 后全部按比例缩放，
60 Hz 专家恢复（0.20 m/s 草莓 6/6）。同时 `record_demos/eval_act_pure` 的 `sim_freq`
映射修正为 20/30/60 → 100/120/240。

训出 `act-60hz-4c`（val 0.059）。评测（0.20 m/s，四类各 6 局）：

| 配置 | 苹果 | 草莓 | 香蕉 | 梨 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 30 Hz（`act-high-4c`，8 局/类） | 4/8 | 4/8 | 4/8 | 0/8 | 12/32 = 37.5% |

## 6.15 触觉传感：视觉+触觉联合（v1.12，负结果 + 可复用管线）

### 6.15.1 触觉信号（仿真真值，9 维）

`bc.build_tactile`：左右指净接触力 → 法向力 `Fn`、不平衡度 `Fasym=|fL_n−fR_n|/Fn`、
摩擦利用率 `rho=|F_t|/Fn`、夹爪开口 `w`、挤压比 `δ`、物体相对 TCP 速度 `v_slip`、
滑移标志、左右指接触位。实测（抓住梨时）：`Fn=37.7 N, Fasym=0.013, w=0.056 m`；
稳定搬运时 `v_slip≈0.007`（正确反映"没滑"）。

### 6.15.2 干净 A/B（同一份数据，只差 9 维触觉是否进模型）

数据：`dta-*`，0.06–0.18 m/s，四类各 50 局（专家 50/50、50/50、39/50、34/50），共 173 局。
两个模型同数据同超参：`act-ta-4c`（触觉，obs 61）vs `act-nota-4c`（无触觉，obs 52）。

| 0.08 m/s（四类各 6 局） | 有触觉 A | 无触觉 B |
| --- | --- | --- |
| 苹果 / 草莓 / 香蕉 / 梨 | 6/6、5/6、2/6、2/6 | 6/6、6/6、2/6、0/6 |
| **合计** | **15/24 = 62.5%** | **14/24 = 58.3%** |
| 峰值法向力（均值） | 40.1 / 26.4 / 25.0 / 10.8 N | 40.3 / 26.7 / 22.9 / 13.8 N |
| 累计滑移（均值） | 12.4 / 154.9 / 39.8 / 45.6 cm | 7.1 / 85.8 / 38.8 / 20.2 cm |
| 抓起后掉落 | 0/1/4/0 | 0/0/4/2 |

0.15 m/s：A 9/24 = 37.5%，B 15/24 = 62.5%（触觉更差）。

**结论：把触觉拼进 state 没有带来成功率或"无损"改善（+4pp 在噪声内，滑移反而更多，
0.15 明显更差）。**

### 6.15.3 为什么无效（三条，均有证据）

1. **夹爪力不可控**：`pd_ee_pose` 只有开/合两档，法向力由物体尺寸决定（实测 40 N / 26 N /
   10–14 N），策略无法"增力/减力"。而文献里触觉的收益主要来自**力作为动作通道**
   （FARM, arXiv:2510.13324）或**滑移触发的增力反射**（T-TO, arXiv:2010.01928）——
   这两条在这个动作空间里都不可用。
2. **没有失败样本**：示教全是成功轨迹，滑移帧占比 0.1–0.7%，滑移辅助头正样本≈0
   （训练日志 `slip 0.000`），学不到"滑移→补救"。
3. **管线自带逐列 z-score**：任何逐列仿射缩放都被归一化抵消（A 与 A2 的 val 完全相同
   0.0608），所以"无量纲化"在这套训练里是无效操作；触觉的价值只能来自**非线性交互**
   或**辅助监督**，而当前数据/动作空间两者都受限。

### 6.15.4 若要真正用上触觉（按性价比）

1. 换**力控夹爪**（动作里加目标夹持力），把 `Fn` 变成可调量 —— 这是文献里触觉起作用的前提；
2. 采**失败/滑移数据**（策略跑闭环、抓空/滑脱的片段），用触觉自动标滑移并训练辅助头；
3. 触觉单独编码成 token 再与视觉 cross-attention（arXiv:2504.13618、2606.06281），
   而不是拼到 state —— 但需要 2–3 倍数据量才看得出收益。

### 6.16.1 采策略闭环的失败片段（补上"示教无失败样本"的缺口）

`scripts/collect_slip.py`：跑带触觉的策略闭环，逐帧保存（`aux_only=True`，只参与滑移辅助损失）。

| 类 | 帧数 | 滑移帧（Fn>5N 且 v_slip>5cm/s） | 失败率 |

| 草莓 | 3359 | 698 | 2/6 |
| 香蕉 | 4601 | 181 | 4/6 |
| 梨 | 4441 | 1057 | 3/6 |
| **合计** | **15150** | **3313（21.9%）** | 11/24 |

### 6.16.2 滑移辅助头（aux 数据 2× 过采样）

`runs/act-ta-slip`（val 0.0553，优于 0.0608）。离线评估（2502 窗口，正样本 23.6%）：

```
滑移头 AUROC = 1.000 | 正样本平均概率 0.988 vs 负样本 0.001
阈值 0.5: 召回 0.99  误报 0.00
```

**这是退化结果，必须说清楚**：滑移标签由 `v_slip` 计算，而 `v_slip` 本身就在观测里（第 54 维），
模型直接读得到。所以这个头没有提供新信息。要有意义，标签必须算在**观测视野之外**
（例如 t+15 时刻的滑移），或把 `v_slip` 从输入里剔除。

### 6.16.3 触觉触发的补救（`--slip-guard`）：滑移降 24%，成功率不变

搬运中检测到滑移（Fn>3N 且 v_slip>5cm/s）→ 立即把搬运步长压到 1.2cm/步。
0.15 m/s、四类各 5 局：

| 配置 | 成功率 | 累计滑移（均值） | 抓起后掉落 |
| --- | --- | --- | --- |
| 无补救 | 7/20 = 35% | 34.0 cm | 5 |
| **`--slip-guard`** | 6/20 = 30% | **25.7 cm（−24%）** | 5 |

**滑移距离确实降了 1/4，但没有转化成成功率**——因为多数失败是"根本没抓住"（`carry=0`，
Fn=0），而不是"抓起来滑掉"；滑移补救对后者有效，对前者无能为力。

### 6.16.4 过程中修掉的一个严重 bug（值得记住）

为"无量纲化"把推理端触觉改成缩放值，但 `act-ta-4c` 是用**原始值**训练的 → 观测分布不匹配，
同一配置从 3/3 直接崩到 0/3。回滚为原始值后恢复 3/3。
**教训：训练/推理的特征变换必须由同一个常量控制；逐列 z-score 会抵消一切仿射缩放，
所以"归一化触觉"在这套管线里本来就是无效操作。**

### 6.16.5 结论

在「固定夹持力的平行夹爪 + 纯模仿学习」条件下：
- 触觉**作为观测**：成功率无收益（A/B 62.5% vs 58.3% @0.08）；
- 触觉**作为补救触发**：滑移距离 −24%，但成功率不涨（失败以"没抓住"为主）；
- 触觉**作为监督**：当前标签可由观测直接读出，退化。

要跨过去需要**力控**（把目标夹持力做成动作维度）或**接触前的预测性决策**
（在闭爪前用触觉历史判断"这一抓会不会滑"，而不是滑了再救）。

## 6.17 触觉迭代三：去泄漏的滑移预测 + 闭爪前重抓（v1.14）

### 6.17.1 修掉标签泄漏

原标签 = `max(slip[t+1..t+10])`，而 `v_slip` 就在观测里 → AUROC 1.0 是读数不是预测。
新标签 = **即将滑移的起始**：当前未滑、且 `t+5..t+20` 内会开始滑（5 帧盲区，强制预测）。
正样本比例 23.6% → 3.3%。

训练：`dta-*(173 局) + sdagger3-*(每类 4 局失败片段，4× 过采样)`，`--slip-head --slip-weight 1.0`
→ `runs/act-ta-onslip`（val 0.0502）。

### 6.17.2 留出集 AUROC（8 局失败片段，**未参与训练**）

| 滑移头 | AUROC | 正样本平均概率 | 负样本平均概率 |
| --- | --- | --- | --- |
| 旧（泄漏，t+1..t+10 max） | 0.611 | 0.460 | 0.328 |
| **新（onset，t+5..t+20 起始）** | **0.813** | 0.590 | 0.155 |

阈值 0.5 下：召回 0.59、误报 0.16、触发率 0.17。**这是"触觉作监督"第一次得到非退化的验证。**

### 6.17.3 闭爪前重抓（`--regrasp`）：类间互补，净收益随速度反转

触发条件：相位=下探、模型命令闭爪、滑移头概率 > 0.5 → 张开 → 下沉 2cm → 再闭。
0.08 / 0.15，四类各 8 局，对照组 `act-nota-4c`（同数据、无触觉、同种子）：

| 类 | 0.08 对照 | 0.08 重抓 | 0.15 对照 | 0.15 重抓 |
| --- | --- | --- | --- | --- |
| 苹果 | 8/8 | 4/8 | 5/8 | 3/8 |
| 草莓 | 8/8 | 5/8 | 8/8 | **0/8** |
| 香蕉 | 2/8 | **7/8** | 5/8 | **7/8** |
| 梨 | 0/8 | **6/8** | 1/8 | **4/8** |
| **合计** | 18/32 = 56.3% | **22/32 = 68.8%（+12.5pp）** | 19/32 = 59.4% | 14/32 = 43.8%（−15.6pp） |

累计滑移（0.08，均值）：重抓 79.5 cm vs 对照 48.7 cm —— 重抓要"张开再闭"，
张开瞬间物体会滑一段，所以滑移距离反而变大。

**解读**：滑移预测确实救回了"弱抓取"类（香蕉 2→7、梨 0→6），但在本来就稳的类上
（苹果/草莓，Fn 高、触发率也高）会误触发并破坏好抓取——0.15 草莓 8/8 → 0/8 就是典型。
即**触发器缺少"该不该干预"的判别**，而不是预测本身不行。

### 6.17.4 下一步（明确）

1. 触发门控：只在 `Fn` 低于类阈值、且 `slip_prob` 连续 N 帧高时才重抓（草莓 Fn≈26N 不该触发，
   而梨 Fn≈14N 该触发）——用触觉本身做门控，不需要新数据；
2. 或把"是否干预"也学出来（辅助头二分类：干预后成功率），标签用闭环 A/B 的结果；
3. 重抓改为"下沉 + 保持闭合"（不张开），避免张开瞬间的滑移。

## 6.18 为什么"草莓 8/8 却被重抓误触发"（v1.15 诊断）

问题：无触觉对照在 0.08/0.15 的草莓是 8/8，加上滑移触发的重抓后掉到 5/8、0/8。
如果抓得很稳，滑移头为什么还会报警？

**答案：草莓在成功搬运时一直在"微滑"，而我的规则把微滑当成了"即将失败"。**

`held` 帧内（物体贴着 TCP）的 `v_slip` 分布：

| 数据 | 类 | held 帧 | p50 | p90 | p99 |
| --- | --- | --- | --- | --- | --- |
| **成功示教** | 苹果 | 494 | 0.006 | 0.184 | 1.051 |
| **成功示教** | **草莓** | 553 | **0.124** | 0.173 | 0.991 |
| **成功示教** | 香蕉 | 660 | 0.045 | 0.182 | 0.705 |
| **成功示教** | 梨 | 618 | 0.007 | 0.033 | 0.688 |
| 失败闭环 | 苹果 | 2025 | 0.172 | 0.322 | 0.492 |
| 失败闭环 | 草莓 | 1090 | 0.152 | 0.233 | 0.501 |

也就是说：**草莓在成功抓取里中位滑移就有 12.4 cm/s**（圆、小、光滑，指面接触面小，
靠摩擦托着走时会持续微转/微滑），而我的触发阈值是 5 cm/s → 必然常触发 → 张开夹爪去"重抓"
→ 把一个本来能托住的水果主动放掉了。

阈值 5 cm/s 对苹果合适（成功时 p50=0.006），对草莓完全不合适——**触觉阈值必须按"类内成功分布"
标定，而不是全局常数**。

另外，尝试用"即将脱离夹爪"（held 由 1→0）做标签也失败：`held` 本身会抖
（成功示教的"即将脱离"率 5.7%，失败闭环 5.4%，不可分）。要可用，需要更稳的夹持判据
（双指接触 + 开口 < 物体宽度 + 连续 N 帧）。

**结论与修法**：
1. 触发门控改为 **类内相对阈值**（`v_slip > max(0.15, 3×该类成功示教 p50)`）+ 连续 2–3 帧；
   按上表，苹果/梨 ≈0.15–0.2，草莓 ≈0.37，香蕉 ≈0.15；
2. 或换成**"掉落预测"**而不是"滑移检测"：标签用"物体与 TCP 距离 > 夹爪半宽"的持续增大，
   并用双指接触稳定判据替代 `held`；
3. 干预动作也应更保守（下沉+保持闭合，而不是张开），避免张开瞬间真的掉。

| 触觉 token + 力通道（`act-tok-force`） | 0/3 |
| + 掉落头（`act-arch3`） | 0/3 |

**结论：把触觉塞进策略（无论拼 state 还是独立 token）都会拖累闭环；力动作通道进一步恶化。**
训练/验证 loss 都很好（train 0.0027），但闭环行为崩（`carry` 不释放、掉落头饱和）——
又一次印证"离线指标 ≠ 闭环可用"。

### 6.20.2 但把掉落预测拆成独立模块，效果很好

`scripts/train_drop_predictor.py`：轻量 MLP（48 维输入 = 5 帧×9 触觉 + 物体距离/是否贴住/带速），
主策略完全不参与。

| 预测器 | 留出集 AUROC | 召回（阈值 0.5） | 误报 |
| --- | --- | --- | --- |
| 策略内掉落头（6.95M 里的一部分） | 0.779 | 0.53 | 0.19 |
| **独立 DropNet（~20k 参数）** | **0.937** | **0.89** | 0.15 |

留出方式：pear/banana 的失败片段整段不进训练（7 个 ep、~2.4k 帧）。

### 6.20.3 接回部署：中性

`act-wide-4c` + 独立预测器触发重抓（阈值 0.7 保守），0.08 四类各 8 局：

| 配置 | 苹果 | 草莓 | 香蕉 | 梨 | 合计 |
| --- | --- | --- | --- | --- | --- |
| 基线 | 8/8 | 8/8 | 8/8 | 4/8 | 28/32 = 87.5% |
| **+ 掉落触发重抓** | 8/8 | 7/8 | 8/8 | 4/8 | 27/32 = 84.4% |

触发几乎不误伤（阈值高），但也**没带来收益**——因为剩下的失败不是"抓起来掉了"，
而是"根本没抓住"（梨 4/8 中的 4 次是 `carry=0`）。掉落预测再准也救不了没抓到的。

### 6.20.4 三条改动的最终判定

| 改动 | 预测能力 | 闭环收益 | 结论 |
| --- | --- | --- | --- |
| ① 触觉独立 token | 与拼 state 相当 | **负**（3/3→1/3） | 不采用 |
| ② 力作为动作通道 | — | **负**（0/3） | 不采用（需真正力控夹爪） |
| ③ 掉落预测触发 | **AUROC 0.937** | 中性（±1 局） | 保留为独立模块/监控 |

**部署仍为 `act-wide-4c`：0.08 87.5%、0.15 96.9%。**

## 6.21 宽度设定点（LeTac 式位置等价力控）：力能调，但调下来就抓不住（v1.18）

### 6.21.1 标定（从 170 局带触觉示教统计"抓持帧"）

| 类 | 抓持时开口 w*（中位） | 抓持时 Fn（中位） |
| --- | --- | --- |
| 苹果 | 0.062 m | 40.3 N |
| 草莓 | 0.034 m | 26.5 N |
| 香蕉 | 0.044 m | 27.3 N |
| 梨 | 0.068 m | 43.1 N |

（注：`qpos` 在 obs 里是 `[7:16]`，手指是 `obs[14]+obs[15]`——一开始用错了列，算出来是负数。）

### 6.21.2 位置确实能改力（静止夹持）

`gripper` 指令 g 与空载开口近似线性：`gap ≈ 0.030 + 0.050·g`。把 g 当"目标开口"用，
夹住苹果时实测：

| g | 实际开口 | Fn | 静止夹住 |
| --- | --- | --- | --- |
| −1.0 | 0.000 | 1.3 N | ✗（水果被挤出） |
| +0.1 | 0.055 | 20.1 N | ✓ |
| +0.3 | 0.064 | 10.4 N | ✓ |

**所以"位置等价力控"在我们仿真里是可行的：40 N 可以压到 10–20 N。**

### 6.21.3 但闭环搬运时，只有"夹到底"能活

用宽度设定点做闭环（0.08 m/s 苹果 5 局）：

| 闭合指令 | 峰值 Fn | 成功率 |
| --- | --- | --- |
| −1.0（基线，闭到底） | 40.3 N | **5/5** |
| −0.5 | 28.5 N | 0/5 |
| −0.3 | 23.8 N | 0/5 |
| 0.0 | 16.7 N | 0/5 |
| +0.1 | 14.4 N | 0/5 |
| +0.2 | 12.0 N | 0/5 |

**结论：在这个仿真里，"能搬住"的最小夹持力就在 ~40 N 附近。** 一旦降到 28 N 以下，
水果在搬运中全部脱落——不管静力上是否够（2 N 重力 vs 10+ N 摩擦），
实际是**接触几何**变差（半闭时只有指尖接触、摩擦锥小）。

所以论文里"轻柔抓取/力上限"的思路，在本仿真**没有可用窗口**：
不是我们不会调力，而是**调下来就抓不住**。要实现"无损抓取"，需要改物理侧
（软指/更高摩擦接触面），而不是控制侧。

### 6.21.4 对"融合触觉"的最终判断

| 触觉用法 | 结果 |
| --- | --- |
| 作观测（拼 state / 独立 token） | 负（62.5% vs 58.3%；3/3→1/3） |
| 作动作通道（第 5 维目标力） | 负（0/3） |
| 作监督（滑移/掉落预测） | **正**（独立 MLP 留出 AUROC 0.937） |
| 作闭环补救（降速/重抓/验证门） | 中性（±1 局） |
| 作力控（宽度设定点） | 力可调但**调下来就抓不住**（28 N 即 0/5） |

**根因**：本任务的失败集中在「接触前对准」和「夹爪物理」，而不是「触点信息不足」。
在只有位置权限 + 硬指 + 低摩擦的设定下，触觉能给的是"监控/告警"，给不了"更好的抓取"。

## 6.22 对准与夹爪物理：渲染截图定位到「夹在果尖」（v1.19）

### 6.22.1 对准不是瓶颈

四类失败局实测：TCP 与水果的**最近距离 0.2–1.0 cm**（dx/dy/dz 均 <1cm）。
策略的接近/预瞄已经很准，不是"没对上"。

### 6.22.2 截图暴露真正问题：只夹到梨的顶端

在闭爪瞬间渲染并放大（`/tmp/opencode/pear_close_zoom.png`）：
两指只接触梨**顶部一小块**（指尖接触），梨的果身在两指下方——抓取点太深（TCP 到果心）。

**扫描抓取高度（专家，0.08，10 局）**：

| TCP 高度偏移 | 成功率 |
| --- | --- |
| 0（原来，果心） | 6/10 |
| **抬高 1 cm** | **9/10** |
| **抬高 2 cm** | **9/10** |
| 抬高 3 cm | 4/10 |

固化到专家：`pear_extra_depth = −0.015`，重采梨示教 → **32/50 → 37/40（92.5%）**。

### 6.22.3 策略侧：重训不迁移，执行层偏置才有效

| 方案 | 0.08 梨 |
| --- | --- |
| 基线 `act-wide-4c` | 4/8 = 50% |
| 用修正示教重训（含触觉 state） | 0/8（且苹果 8/8→6/8） |
| 用修正示教重训（`--no-tactile`） | 0/8（香蕉 8/8→0/8，训练不稳） |
| 梨单类模型（37 条修正示教） | 1/10 |
| **基线 + 执行层 z 偏置 +1.5cm（仅梨）** | **5/8 = 62.5%** |

结论：策略的 z 精度约 ±1cm，**重现不了 1.5cm 的抬高**；把它放到执行层（按类的工具偏置）
才有收益。`--z-bias 0.015` 只对梨开（香蕉加偏置会 8/8→0/8）。

### 6.22.4 夹爪物理的两次尝试（均无效/有耦合）

| 方案 | 结果 |
| --- | --- |
| 水果材质摩擦 ×2/×4 | 梨 6→6→8/10，但**香蕉 10/10→0/10**（水果-传送带摩擦同时变大，水果不再被带面驱动） |
| 夹爪侧软指等效 `pad_mu`（黏性摩擦上限 μ·Fn） | 梨 6/10、策略 4/8，**完全无变化** |

→ 摩擦不是主要矛盾；**接触几何（夹在果身还是果尖）才是**。

## 6.23 灵巧手：环境缺陷导致此前数据全部作废（v1.20，重要更正）

### 6.23.1 结论先行：撤回此前的灵巧手数据

之前报过「梨：平行夹爪 8.8N vs Ability Hand 最好 >60N」。**这些数字作废**——
`xarm7_ability` 在本机 ManiSkill 里物理不稳定，所有读数都是 NaN 爆炸后的残留值。

### 6.23.2 证据（三步递进）

1. 在我们的 `FruitSort-v1` 里，**连"保持当前位姿"**（action = 当前 qpos）都 20–30 步内 NaN：

robot_base=(0,-0.50,0.4) → 30 步保持位姿 NaN=True
robot_base=(0,-0.90,0.0) → 30 步保持位姿 NaN=True

3. **用 ManiSkill 自带的 PushT-v1 + xarm7_ability 也 NaN**（不是我们场景的问题）：

```
PushT-v1 + xarm7_ability: NaN = True | qpos[1]=+nan
```

### 6.23.3 期间踩过的坑（都已定位，留档）

- pinocchio 的 URDF frame 与 SAPIEN link 原点不一致（指尖相差 ~0.5m）；但**基座变换已标定正确**

## 6.24 灵巧手 vs 平行夹爪：**可复现的对照结果**（v1.21）

### 6.24.1 先换到稳定的手（准入门槛）

`xarm7_ability`（Ability Hand）在本机 ManiSkill 里 NaN（见 6.23），改为扫本机其他组合，

| 机器人 | 结果 |
| --- | --- |
| `xarm7_ability`（5 指 10 关节） | ✗ NaN |
| `dclaw`（Google D'Claw，3 指 9 DoF） | **✓ 稳定** |
| `trifingerpro`（3 指 9 DoF） | ✓ 稳定 |

顺带修掉两个初始化 bug：任务里 `dof==9` 被硬编码成 panda 关节（D'Claw 也是 9 DoF），
以及 `hand_idx` 把 `joint_f1_0` 这类名字误当成臂关节。

### 6.24.2 四类抓取强度（同协议：放果→闭指→递增上拉，单位 N）

| 类 | 平行夹爪（panda） | **D'Claw（3 指）** | 差 |
| --- | --- | --- | --- |
| 苹果 | 8.0 | 8.0–8.5 | ≈ |

| 香蕉 | 7.8 | 6.2 | −21% |

**同一配置重复测量已稳定**（D'Claw 梨：3 个放置深度分别 9.5 / 9.0 / 9.5 N，不再出现

### 6.24.3 结论

**在这套任务/物体/接触条件下，常用的开源灵巧手（D'Claw）并不比平行夹爪抓得更好**：
四类里三类持平或略差（−17%~−21%），只有梨略好（+5~8%），全部落在 ±20% 内。

这与 6.22 的诊断一致：瓶颈是**物体与手指的接触几何**（夹果身还是果尖），
而不是"手有几个指头"。换更灵巧的手并不会自动解决它。

### 6.24.4 局限（必须说明）

- D'Claw/TriFinger 是**固定基座**的手，只能做"抓+拉"的抓取强度测试，**不能做传送带分拣**；
  分拣任务需要"臂+手"，而本机唯一的"臂+手"组合 `xarm7_ability` 是 NaN。
- 因此**任务级**（四类各 8 局、成功率/节拍/掉落 vs `act-wide-4c`）仍然无法用灵巧手产出。

## 6.5 已定位的模型缺陷（v0.6 诊断）

用 20 组对照实验（`/tmp/vision_diag/`）定位到两个训练侧问题：

1. **动作头有"悬停不动点"**：z 用绝对值回归 + 示教里悬停帧占多数，闭环目标 z 平均比水果高 7.7 cm，
   进入抓取区后只有 2% 的帧低于 +3 cm。修复方向：z 改为预测 **Δz**（相对当前 TCP），或对下探帧过采样。
2. **夹爪头类别极不平衡**：闭合帧仅占 18%，BCE 无 pos_weight，模型在 600 个专家帧上从未预测闭合。
   修复方向：`pos_weight≈4.5` + `grip_head.bias` 初始化到 logit(0.18)。

当前的工程绕法是：**夹爪与近距伺服改用几何判据**（d<0.05 且水果在抓取区），模型只负责远距目标与水果选择。
这也是 `docs/gripper-timing.md` 的结论：1 bit 的"何时闭爪"不该交给回归头。
