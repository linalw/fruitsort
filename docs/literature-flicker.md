# 目标"闪断"导致放弃：前人怎么解，哪条对我们适用

> 现象：学习式分割后端在**感知指标上**与经典持平（GT 召回 100%、3D 0.21 cm），
> 但闭环几乎不成功（1/20）。诊断说差在"逐帧检出/轨迹连续性"。
> 这篇把这个问题对到文献上，并给出**我们实测的结果**——其中一条经典方法被证伪了。

## 1. 问题的学名

这是 **tracking-by-detection 的目标漏检（miss detection）→ 轨迹中断（track fragmentation）**
问题，文献里属于 MOT（multi-object tracking）与"检测器-跟踪器耦合"的范畴。
我们的特殊之处：**单帧漏检会直接让上层控制器放弃目标**（判 ghost），
所以对"闪断"的容忍度比一般 MOT（只要 ID 不换就行）低得多。

## 2. 文献里的四条主线

| 主线 | 代表工作 | 核心思想 |
| --- | --- | --- |
| **低分框二次关联** | **ByteTrack**（[2110.06864](https://arxiv.org/abs/2110.06864)） | 高分框先关联；**低分框只用来把没配上的轨迹续上**，不新建。作者的原话就是"低分框（遮挡物体）被直接丢掉，造成漏检与轨迹碎片" |
| **遮挡感知关联** | OA-SORT（[2603.06034](https://arxiv.org/abs/2603.06034)）、Measurement-wise Occlusion（[1805.08324](https://arxiv.org/abs/1805.08324)） | 显式建模"被谁挡住/挡了多少"，用遮挡状态修正关联代价；仍以卡尔曼/匀速运动为底 |
| **小目标切片推理** | **SAHI**（[2202.06934](https://arxiv.org/abs/2202.06934)）、ROI-Gated SAHI（[2608.23923](https://arxiv.org/abs/2608.23923)） | 把大图切块（或放大）逐块推理再合并，让小目标在每块里"变大" |
| **高分辨率特征** | HRDNet（[2006.07607](https://arxiv.org/abs/2006.07607)）、QueryDet（[2103.09136](https://arxiv.org/abs/2103.09136)） | 在网络结构上保留高分辨率分支/稀疏查询，代价是训练与算力 |

## 3. 我们逐条试了哪条

### 3.1 ByteTrack 的低分二次关联 —— **实测不适用**

我按 ByteTrack 的思路实现了两阶段：分割用 0.60 出掩码做正常检测，再**用 0.30 出同一批掩码**
只喂给跟踪器的第二阶段（门限 0.12 m，不新建轨迹）。
`scripts/diag_track_gaps.py` 直接量"每个真值件每一帧是否还有活着的轨迹"：

```
classic                    轨迹覆盖  88.1%   断档次数  406   断档中位 1.0 帧
learned(1阶段)              轨迹覆盖  85.6%   断档次数  449   断档中位 1.0 帧
learned(2阶段 low=0.3)      轨迹覆盖  85.6%   断档次数  449   断档中位 1.0 帧   ← 完全没变
```

原因查到了：**我们的"漏检"不是"低分"，而是"没有响应"**。

```
40 帧: th0.60 掩码 141 | th0.30 掩码 141        ← 降低阈值一个都没多出来
低分掩码的平均概率: 0.86 / 0.91 / 0.93          ← 有响应的都是高分
```

ByteTrack 的前提是"物体还在，只是分数低"（框还在）；我们的网络在目标被挡/太小时
**整块概率塌到 0**，低分框根本不存在，所以这一招无从下手。

### 3.2 GT 口径复核：其实**没有丢检**

之前"学习式召回只有经典的 82%"是**相对经典的检出数**算的，而经典会多报（同一件检两次、
或把非果物检成水果）。按真值重算：

```
真值件×帧 80
  classic  召回 100.0%   检出/帧 3.73
  learned  召回 100.0%   检出/帧 3.52
```

**无遮挡时两者都 100%**——所以学习式的闭环问题不在"看不见"，而在**被夹爪挡住的
那 1–2 秒**（面积掉到 0.70–0.77、长轴 −7 mm）以及由此引起的几何/类别抖动。

### 3.3 SAHI 式的"放大再推理"—— 在无遮挡帧上没有增益

同一批帧把输入放大 2× 再推理：1× 和 2× 的 GT 召回都是 **100%**。
说明我们的瓶颈不是小目标分辨率（视场虽宽，但果实 15–25 px 已经够网络用），
**不需要**引入切片推理的复杂度。

## 4. 结论：该抄哪一条

按"对我们的失效模式是否对症"排序：

| 方法 | 是否适用 | 理由 |
| --- | --- | --- |
| **ByteTrack 低分关联** | ❌ 已证伪 | 漏检是"零响应"，没有低分框可捞 |
| **SAHI 切片/放大** | ❌ 无增益 | 无遮挡帧召回已 100% |
| **遮挡感知关联 + 运动模型**（OA-SORT 一类） | ✅ **对症** | 我们的失效点就是"夹爪遮挡那几秒"；需要的是"遮挡期用运动学续推 + 遮挡解除后重关联"，而不是低分框 |
| **模板/掩码传播**（用遮挡前的掩码预测当前形状） | ✅ **对症** | 面积 0.70–0.77 是"少了半块"，用上一帧形状补最直接 |
| 高分辨率骨干（HRDNet/QueryDet） | ⚠️ 不必要 | 召回已满，代价大 |

**下一步（按性价比）**：

1. **遮挡期的运动学续推 + 形状冻结**：已有 `_last_geom`，把它升级成"按带速平移的模板"，
   在遮挡解除时用 IoU 重新绑定（而不是靠中心距离）；
2. **遮挡感知的关联代价**：把"该像素被机械臂占据"（深度图上手臂的 z 明显高于带面）
   作为可见性权重，降低遮挡目标的关联阈值——这是 OA-SORT 的 OAM 思路的简化版；
3. 若仍不够，再考虑**腕部相机**在抓取瞬间接管定位（眼在手上，天然不被自身遮挡）。

## 6. 按文献思路继续挖，挖出一个真 bug

文献里"遮挡期用运动学续推"这条促使我去查**适配器在丢检时的兜底**。加了一行调试输出
（`FRUITSORT_DEBUG_GHOST=1`）后真相是：

```
[ghost] apple: miss=0  last_x=+0.30  hold_x_max=0.3
[ghost] apple: miss=0  last_x=+0.34  hold_x_max=0.3
```

`miss=0` 说明**上一帧还在检**；这一帧恰好丢了一次，而因为果子已经走到 `x≈+0.30`
（`hold_x_max` 的边界），适配器直接把替身**瞬移到带子上游的占位 `clip_x=-1.10`**——
状态里出现 3 m 的跳变，控制器于是判 `ghost` 放弃。

**修法**：兜底改成"**冻结在最后位置**（速度记 0）"，只有"从来没检到过"才用刚上料的占位。
修完实测：

| 后端 | 修前（同协议 60 s × 1 局） | 修后 |
| --- | --- | --- |
| classic | 1/3（seed 60002） | **3/5**（s60002 1/1、s60003 0/2、s60004 1/1、另 1/1） |
| learned | 0/4 | **0/8**（仍不成功） |

所以：**经典后端受益于这个修复**（少了一次"瞬移导致放弃"），而学习式仍然不行——
它的问题是"整块概率塌陷"（遮挡时没有任何响应），不是"丢一帧就被瞬移"。
这也再次印证：③ 关闭为"感知层可替换、闭环不采纳"是对的。
