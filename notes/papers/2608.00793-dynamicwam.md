# DynamicWAM: Dual-Path Motion Conditioning for World–Action Models in Dynamic Manipulation

> **arXiv** 2608.00793v2（cs.RO，v2 2026-08-06）· **机构** PKU-PI Lab / 北京大学 / ePyBot Intelligence / 新加坡国立大学 / 清华大学
> **项目页** https://dynamicwam.github.io/ · **代码** https://github.com/Autumn1337/DynamicWAM · **权重** https://huggingface.co/KhalilGao/DynamicWAM
> 标签 #WAM #dynamic-manipulation #optical-flow #RTC

## 一句话结论

动态抓取的瓶颈不是 backbone 不够大，而是**单帧观测本身歧义**：给 World–Action Model 补两路便宜的运动条件（历史光流渲染帧 + 12 维运动学描述子），DOMINO 成功率从 22.7% 拉到 38.2%；再用 RTC 把 173.7 ms 的推理延迟藏进执行里，真机 12 任务从 42.08% 提到 46.67%。最值得抄的是那个 12 维描述子和"只从固定外部相机算 flow"的工程取舍。

## 要解决的问题

- **同一帧、不同运动**：视觉上几乎相同的当前帧可能来自相反方向的运动（Fig.1 两个 case），所需接触时机完全不同。只 condition 当前帧的 WAM 必错。
- **同步执行的过期问题**：WAM 在 chunk 边界才查询一次大 backbone，chunk 还没执行完预测已经陈旧。
- **光流表征的两处信息损失**（这是全文最扎实的观察）：
  - 逐帧按 99 分位归一化渲染 ⇒ `ρ(αU) = ρ(U)`，绝对位移尺度被抹掉；
  - 渲染图不含经过时间 `Δτ`，速度无法从图像反推。
  - 结论：flow 图像给"哪里在动、怎么组织"，**给不了"多快、多远"**。
- 现有加速路线（跳过未来想象 / 压缩去噪）都不处理"运动条件"这件事。

## 方法核心

### 0 问题设定

每个 chunk 边界 t 接收多视角观测 `O_t`、语言 `ℓ`、本体 `s_t ∈ R^14`（DOMINO）或 `R^7`（真机），输出动作 chunk：

```
A_t = a_{t:t+Ha-1},  Ha = 16,  控制间隔 100 ms ⇒ chunk 覆盖 1.6 s
```

### 1 骨干

- 紧凑视频专家：12 层、d=2048、FFN 8192、16 头，从 **Wan2.2-TI2V-5B** 蒸馏（学生层对齐教师层 {1,2,4,6,8,11,14,17,20,23,26,30}）。
- 动作专家：12 层、d=768、FFN 3072。
- VAE（Wan2.2）与文本编码器（UMT5-XXL, max 512）全程冻结。
- 每个 block 内 video / action query 都 attend 到两路拼接的 KV（**双向** joint world–action attention），video token 加 3D RoPE。
- action stream 共 25 token：1 state + 16 noisy action + 4 kinematic + 4 register。**decoder 只读 state/action token，动作空间不变**（这点对迁移很关键）。
- 未来预测：8 帧 RGB @192×160 → latent `[48,2,12,10]`；Stage-3 可训参数 988.8M（视频 849.2M + 动作 139.6M）。

### 2 history-flow 路径（空间结构）

- 历史切成 K=4 段，端点 `n_k = t-(K-k)Δ`，`Δ=4` 个 policy step；原始帧偏移 `[48,36,24,12,0]`（全局时间降采样 r=3）。
- 在**固定头部相机**上算稠密 Farnebäck 光流：RGB resize 到 64×64 转灰度，pyr 0.5 / 3 层 / win 15 / 3 iter / 多项式 n=5 / σ=1.2。
- 前后向一致性过滤：`‖U(p)+V(p+U(p))‖² < ε_rel(‖U‖²+‖V‖²)+ε_abs`，ε_rel=0.01、ε_abs=0.5；有效像素 <10% 则整段标 invalid。
- 渲染：方向→hue，幅值

```
r_k(p) = min( ‖Û_k(p)‖₂ / q(Û_k), 1 ),   q = 99 分位
```

- `Z_t^c = E_VAE([R_1,...,R_K, O_t])`——**和外观走同一条 latent 通路，不引入额外 motion encoder**。

### 3 kinematic token 路径（尺度与时间）

每段有效像素集 Ω_k 上算 12 维描述子（式 6–11）：

```
d_k = mean(U),  d̄_k = mean(‖U‖),  d99_k = p99(‖U‖)
v_k = d_k/Δτ_k,  v̄_k = d̄_k/Δτ_k,  v99_k = d99_k/Δτ_k
a_k = (v_k - v_{k-1}) / (c_k - c_{k-1}),  c_k = (τ_{k-1}+τ_k)/2
m_k = [d_k, d̄_k, d99_k, Δτ_k, v_k, v̄_k, v99_k, a_k, ‖a_k‖₂] ∈ R^12
```

- 用数据集统计量标准化；无效段用可学习的 invalid-interval / invalid-acceleration embedding。
- 两层 MLP + interval-position/type embedding → `e_1..e_K`，插进 action stream（不替换 state/action token）。

### 4 训练目标

条件 flow matching，两个模态各自采样噪声与噪声级：

```
x_q^σ = (1-σ_q)x_q + σ_q ε_q,   u*_q = ε_q - x_q,  q ∈ {v,a}
L = E‖û_a - u*_a‖² + λ_v E‖û_v - u*_v‖²
```

三阶段（8×H100，global batch 128，AdamW，bf16）：
1. **视频专家蒸馏** 80k 步：GT flow matching + 隐状态蒸馏（学生 {1,3,5,7,9,12} 回归教师 {1,4,8,14,20,30} 的 PCA 投影激活）+ 运动蒸馏（学生 {6,8,10,12} 匹配教师 token 的时间差分；权重 0.2→0.1→0 @ 35%/75% 进度）。
2. **动作专家预训练** 80k 步，视频冻结、`λ_v=0`。
3. **联合精修** 40k 步，`λ_v` 从 0.01 退火到 0.001（前 2k 步）。
- 真机微调同流程但缩短为 8k / 15k / 8k 步（1,200 条数据）。

### 5 推理与异步执行

- 动作 10 步去噪；**视频只在 step {0,1} 做全前向，之后复用 cached video KV** ⇒ 550 ms → 173.7 ms，模型数学上不变。
- RTC：滚动动作队列，剩余 <4 步时异步预取下一 chunk，重叠区 4 步、`γ_max=0.5` 衰减合并。
- DOMINO 评测**故意关掉 RTC**，以匹配 benchmark 的同步协议（比较才干净）。

真机失败分布（50 次失败）：**时机错误 42%**、横向错位 26%、丢跟踪 18%、接触后滑落 10%、其他 4%。

## 世界模型三问（按任务清单）

- **物体运动怎么表示**：没有显式物体轨迹，只有 (a) 4 段 flow 渲染帧进 VAE latent；(b) 12 维数值描述子进 action token。未来是 8 帧 RGB latent（不是 mask、不是 3D）。
- **未来帧怎么预测**：视频专家做条件 flow matching，一次出 8 帧 latent；查询时只用 step 0/1 的 video 前向（缓存复用）。未来帧间隔正文未给，按 100 ms 控制周期量级约 0.8 s。
- **推理速度**：173.7 ms/query（≈5.8 Hz），含预处理、光流、token 构造与全去噪；RTC 后有效节拍由 1.6 s chunk 决定。
- **是否需要大规模预训练**：**是**。视频专家来自 Wan2.2-TI2V-5B，Stage-1 要 80k 步才把 5B 蒸成 12 层。

## 对 Fruitsort 的可执行建议（单 Franka + 传送带，苹果/草莓/香蕉/梨）

### 先纯经典跑通（把两路"降级"成等价物）

1. 固定外部 D435i 做唯一"运动相机"（论文也只用固定头相机算 flow，腕部会丢目标）→ 背景差分 / HSV+深度阈值得到水果 mask → 质心 + 卡尔曼（传送带匀速，CV 模型几乎完美）。
2. 论文那两路可以被经典量直接替代：flow 路径 ≈ 卡尔曼状态与速度场；kinematic token ≈ 显式的 `v, a, Δτ`（传送带速度由编码器/标定给出，比图像估计更准）。
3. 拦截点用解析解：给定带速 `v_b`、臂最大加速度与当前末端位置，解 `min_t ‖p_fruit(t) - p_reachable(t)‖`（含夹爪闭合时间补偿）。这已经能吃掉论文里"timing error 42%"那一大类失败。
4. 夹爪闭合超前量（lead time）用一次性标定，不学习。

### 值得后续接学习的（按性价比排序）

1. **12 维运动学描述子 → 小 MLP / BC 策略的额外输入**：最低风险，不改动作空间，不改视觉 backbone。我们甚至可以把描述子扩成 14 维（加带速、加"距抓取窗口剩余时间"）。
2. **RTC 异步 chunk 执行**：与模型无关的纯工程收益（+9.17 点，其中 RealCore +4.58、RTC +4.59）。先做这个比换模型划算。
3. **历史 flow 帧拼进 VAE 通道**：如果之后上 flow-matching policy，这个 trick 不需要额外 motion encoder，且能解决"同一帧不同运动"的歧义——正是传送带反向/变速场景。
4. **视频 KV 缓存 + 只在头两步做视频前向**：任何 WAM 都该这么做，550→173.7 ms 的收益。

### 不建议现在做

- 5B 教师 + 三阶段蒸馏（8×H100、200k 步）。我们单卡 5090 32GB 装不下"教师 + 学生 + fake-score"三份。
- 视频分支本身：论文**没有**"去掉视频预测、只留 flow+kinematic"的消融，所以"视频世界模型对抓取到底贡献多少"是空白。我们的任务（抓取+投放）语义简单，先假定贡献有限。

### 单臂适配细节

- DOMINO 是 head + 双腕；真机是两固定相机。我们：外部相机算 flow / mask / 卡尔曼，腕部只喂 RGB（论文同样规定腕部不参与 mask/flow 历史）。
- 动作空间 7 关节 + 1 夹爪，与本文真机设置一致，可直接沿用"decoder 只读 state/action token"的做法，保证换条件不改动作语义。

## 复现成本与风险

| 项 | 估计/事实 |
| --- | --- |
| 训练硬件 | 8×H100（论文），global batch 128；单 5090 无法复现 Stage-1 蒸馏 |
| 推理硬件 | 论文延迟在 **RTX 5090 32GB** 上测得（与我们同卡），173.7 ms 可参考 |
| 可训参数 | Stage-3 988.8M（视频 849.2M + 动作 139.6M）；显存未报 |
| 数据 | DOMINO 10,500 条；真机 1,200 条 / 12 任务（100/任务） |
| 训练时长 | 未给出（只有步数 80k/80k/40k） |
| 权重 | HF 有 `KhalilGao/DynamicWAM`，代码仓库已公开 |

风险：
1. **全程依赖 2D 图像运动 + 固定外参**；作者自认不区分目标与其他运动区域，对遮挡、背景变化、视角变化敏感（背景 shift 时 70 → 25）。
2. 传送带上多个水果同时移动 = 多个运动区域混杂，flow 会一起被编码，论文没处理"目标选择"（它靠语言指令，我们靠类别/位置规则反而更简单）。
3. 草莓/香蕉可变形易滚，论文失败里 10% 是 slip，且附录明确说光滑/可变形物体更难；我们的夹爪与吸盘方案要单独验证。
4. 真机颗粒度粗（每任务 20 trials、12 任务），统计功效有限，别把 46.67 vs 23.75 的差值当成线性可预期收益。

## 原文关键片段

1. "Optical flow naturally describes where motion occurs and how it is organized in image space... Yet optical-flow frames are commonly rendered with per-frame magnitude normalization, which removes their global displacement scale."
2. "Per-frame normalization removes absolute displacement scale: for α > 0, ρ(αU) = ρ(U)... The rendered image also omits the elapsed time Δτ_k between endpoint frames, so velocity cannot be recovered from R_t alone."
3. "The action decoder reads only the original state–action tokens, so the robot action representation remains unchanged."
4. "With 10 action denoising steps, full video forwards run only at steps {0, 1}; subsequent steps reuse cached video activations while updating action tokens only. This reduces per-query latency from ≈550 ms ... to 173.7 ms without changing the mathematical model."
5. "Timing error (42%): gripper closes early or late relative to target passage, most common on Level 1 linear tasks at higher speeds."

## 存疑 / 未说清

- 未来 8 帧的时间间隔没写，无法判断预测视野。
- 未做"去视频分支"消融 ⇒ 视频世界模型的实际贡献不明。
- 12 维描述子是图像平面像素量（px, px/s），跨相机/跨分辨率迁移需要重标定统计量；我们换相机就得重算。
- 真机与仿真都靠脚本化目标运动（遥控车、转台、传送带），没有"人递过来"这类非匀速、非可预测运动。
