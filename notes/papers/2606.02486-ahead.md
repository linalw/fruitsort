# AHEAD：在 VLA 特征空间里"预判未来"的动态操作外挂

> **arXiv**: `2606.02486v2` [cs.RO] · 2026-10-03 · **CoRL 2026** (Austin)
> **机构**: Carnegie Mellon University, Robotics Institute
> **作者**: Shahram Najam Syed\*, Arthur Jakobsson\*, Haoran Hao\*, Jeffrey Ichnowski（\* 共同一作）
> **代码/项目页**: 正文与 arXiv abs 页**均未给出**代码或项目页链接（未在正文找到）；第一作者主页 hoar012.github.io 上列出该文 "Paper | Project"。**无开源实现**

## 一句话结论

不需要重训 VLA：在**冻结的 VLA 视觉编码器输出（patch token）上**接一个 4.9M 参数的"运动感知潜空间世界模型"，把**预测出的未来 patch token 拼回 token 网格**喂给原来的 action decoder，就让 7B OpenVLA 在动态任务上从 ~50% 涨到 79–97%。核心洞察是"**预测哪里**（语言+光流显著性）比"预测多少"更决定算力预算，而**预测多远**应该由不确定性自适应决定（实测平均只用 3–5 步）。

## 要解决的问题

- VLA 假设"观测到执行之间场景静止"。物体一动，**感知-执行延迟 > 可抓取时间窗**，策略就去抓物体"曾经在"的位置，夹爪在物体后方空抓。
- 两条已有路线都不解决"预测多少/多远/多快"：
  - **反应式/双系统**（ACT、Streaming DP、HiRT、DynamicVLA、VLASH）：只缩短 stale window，不消除；速度越高残余延迟占比越大。
  - **世界模型**（Dreamer、TD-MPC2、视频生成、LaDi-WM）：整场景定长 rollout，在像素空间或需联合训练，推理超出反应延迟预算。
- 目标：一个 **predict-then-act wrapper**，保持 VLA 冻结、语言 grounding 不变，在 Δt_max ≈ 200 ms 内完成"观测→预测未来→出动作"。

## 方法核心（含关键公式/伪代码）

### 0. 记号与整体数据流

VLA 视觉编码器 `φ: o_t → v_t ∈ R^{N×d}`（N=196, d 为 patch 维）；语言编码器给 `e_ℓ`；动作解码器 `π(v_t, e_ℓ) = a_t`。AHEAD 只改**喂给 π 的输入**：`a_t = π(v̂_{t+K}, e_ℓ)`。

```
每步 t：
  1) RAFT 算 3 帧光流 → patch 池化 → 每 token 速度 V_i、差分得加速度 A_i
  2) ṽ_t = [v_t ; V_i ; A_i] ∈ R^{N×(d+4)}
  3) 语言-运动显著性 → 选 |S| ≈ 30–60 个 token（N=196 中）
  4) 4 层 Transformer encoder → 紧凑潜变量 z_t ∈ R^256
  5) 条件流匹配 rollout：S=5 条样本，5 步 Euler，逐 token 更新 V_k = V_0 + A·k·Δt
  6) 每步算样本方差 ū_{t+k}；ū > τ_u 即停（否则到 K_max=10）
  7) MLP decoder → v̂_{t+K}^(S)；feature alignment 层对齐到 decoder 偏好流形
  8) 拼回原网格：i∈S 用 v̂[i]，否则保留 v_t[i] → 冻结 π 出动作
```

### 1. 语言-运动显著性（空间算力分配）

- 光流：RAFT 对 `o_{t-2}, o_{t-1}, o_t` 求流场，16×16 区域平均池化得 `V_i = AvgPool_i(F_{t-1:t}) ∈ R²`。
- 加速度：两段流场差分 `A_i = (V_i − V_i^{prev}) / Δt`。
- 语言相关性：`M̃_i = σ(CrossAttn(ṽ_t, e_ℓ)) ∈ [0,1]^N`，再做 **1-token 形态学膨胀** 补物体边界。
- 运动下限（式 1）：`M_i = max(M̃_i, α_motion · 1[‖V_i‖ > τ_flow])`，`α_motion = 0.5`；**τ_flow 用静态场景下 per-token 速度的 99 分位标定**（纯相机噪声）。
- 选择集：`S = { i : M_i > 0.2 }`，实测 196 中 30–60 个。
- **自身机械臂 patch 要剔除**：用正运动学 + 相机外参把连杆几何投影到图像，覆盖到的 patch 排除出 S（世界模型没有动作条件，预测不了机器自运动）。这一步把 Ballistic Catch 从 87.4% 提到 92.2%。

### 2. 运动条件世界模型（条件流匹配 + 解析运动学外推）

- rollout 递推：`z_{t+k} ~ p(z_{t+k} | z_{t+k-1}, V_k^(S), A^(S))`，k=1..K。
- **关键 trick —— 别让网络学物理**：
  `V_k = V_0 + A · k · Δt`（式 3），加速度由光流差分给定，网络只负责"特征怎么演化"。
- 采样：条件流匹配 `dz/dτ = v_θ(z_τ, τ | z_τ, V_k, A)`，**5 步 Euler** 就够（扩散要 100+ 步 ≈ 380 ms，超预算）；S=5 条并行样本同时给均值与方差，**不确定性免费**。
- 速度噪声：每条样本注入 `σ = 0.05·‖V_i‖` 的高斯噪声，使"对速度敏感"的轨迹发散、"鲁棒"的轨迹收敛；该方差与真实预测误差相关系数 **r = 0.78**。
- 潜空间维度 d_z=256，encoder 4 层 / 8 头，decoder 为 per-position MLP；总参数 4.9M（encoder 2.6M + 动力学 1.1M + decoder 0.8M + 显著性 0.3M + 对齐 0.1M），占 7B 的 <0.1%。

### 3. 自适应时域早停（时间算力分配）

`ū_{t+k} = (1/S) Σ_j (1/|S|) Σ_{i∈S} ( z_{t+k}^{(j)}[i] − z̄_{t+k}[i] )²`（式 4）；
`ū_{t+K} > τ_u` 即停，否则 K_max。超参：`K_max = 10`，`τ_u = 训练集 ū 的 90 分位`。**实测平均只走 3–5 步**；恒速场景下与固定 K=5 等价，混沌场景（Plinko）才显出价值（1600 ms 窗口下 48.6% vs 固定 K=5 的 31.4%）。

### 4. 训练

- 两阶段：① **操纵视频预训练**（EPIC-Kitchens ≈50K、Something-Something V2 ≈220K、DROID ≈76K、Bridge V2 ≈60K、CALVIN ≈100K、OXE xArm ≈150K，共 ≈656K 序列；三阶段课程：线性运动 → 旋转/多物体 → 混合 + 域相似度加权）；② **≈200 条本机 xArm 7 轨迹**微调 5 epoch。
- 损失：encoder/decoder 用 rollout 上的 MSE（`K_train = 8` 步自回归）；动力学用条件流匹配损失；**对齐层单独训练**，直接优化动作误差 `L_align = ‖π(g_align(v̂_{t+k}), e_ℓ) − π(v_{t+k}, e_ℓ)‖²`。分开训练是为了避免"MSE 重建"与"下游动作精度"的优化冲突。
- 预训练 8×H100 200K steps ≈ 96 GPU-h；对齐层 1×H100 ≈ 4 GPU-h；微调 1×H100 ≈ 2 GPU-h。

### 5. 延迟预算（H100, 224×224, bf16）

| 组件 | 延迟 |
| --- | --- |
| RAFT 光流 ×2 | ≈20 ms |
| 运动池化 + 拼接 | ≈2 ms |
| 世界模型（S=5, 5 步 Euler） | ≈40 ms |
| decoder + feature alignment | ≈6 ms |
| VLA 前向（并行解码） | ≈70 ms |
| 框架/IO | ≈20 ms |
| **合计** | **≈158 ms** |

- 158 ms 是**重规划间隔**，不是控制频率；动作块以 **30 Hz** 执行，wrapper 比纯反应式循环多 ≈68 ms，3–5 步前瞻正好覆盖这点延迟。
- 真机用单张 RTX 4090，**171 ms/action step**。

### benchmark 的动态任务怎么定义（可直接抄的场景设计）

- **恒速组**：传送带 + 红杯（**5–25 cm/s**）、横梁滑杯（5–20）、杆推杯（8–22）、滚球（10–30 cm/s）。
- **加减速组**：同拓扑，但传送带速度线性升/降、杆推加摩擦减速、滚球在**5–15° 斜面**上受重力加速。
- **复杂组**：气垫球（无摩擦面）、弹道接球、多物体（3–5 个）、把静止物放进**移动的盒子**（10–20 cm/s）、多球、**遮挡**（300–600 ms 看不见）、**飞行中途偏转**、语言+多物体。
- **压力测试组**：多次反弹、遮挡+偏转、Plinko 落钉板。
- 成功判据举例：抓取要求"所有手指接触 + 抬升 ≥10 cm + 保持 3 s"；接球要求"球首次竖直速度转正时在网内"；放盒要求"盒子离开工作区时物在盒内且全程未触桌"。

## 对 Fruitsort 的可执行建议（传送带动态分拣：苹果/草莓/香蕉/梨，单 Franka 臂）

### A. 先做"零训练"的解析拦截基线（最优先，1–2 周）

AHEAD 的 **Track-and-Intercept 基线**本身在恒速场景拿到 **86.8%**，说明"检测 + 恒加速拟合 + 把画面 warp 到预测位置"性价比极高，且不需要世界模型：

1. 感知：YOLO/RT-DETR 出 2D 框 + 深度出 3D 质心（或 FoundationPose）。每帧打时间戳 `t_k`。
2. 拟合：对最近 5 帧质心做最小二乘，拟合 `p(t) = p0 + v·t + ½a·t²`（与 AHEAD 的 Track-and-Intercept 完全一致；传送带上 a≈0，滚动水果 a 为重力分量）。
3. 拦截点选择：解 `t*` 使
   `p(t*) ∈ W`（Franka 可达工作空间，建议留 3 cm 余量）且
   `t* ≥ t_now + t_replan + t_close + t_servo`（最小提前量），
   在可行解中取 **`t*` 最早**者（传送带上等价于"最靠上游、行程最短"）。若无解 → 放弃该果（推入旁路）。
4. 控制：TCP 走 `p(t*)` 的直线/五次多项式插值，时间参数化到 `t*`；**夹爪在 `t* − t_close` 开始闭合**（`t_close` 用实测：命令到两指接触约 80–150 ms 量级，需自测标定）。
5. 收益参考：这一层就能把"0 cm/s 96% → 20 cm/s 0%"的悬崖抬起来（AHEAD 表 2 显示纯反应式基线的悬崖位置）。

### B. 若走 VLA 路线：把 AHEAD 的"显著性 + 自适应时域"当算力预算工具

- **预测时域怎么定**（关键，别照抄 K_max=10）：
  `T_lead = t_replan + t_close + t_servo_margin`，
  `K = ceil(T_lead / Δt_frame)`，且用 `K_max` 截断。
  以本机实测量级估算：若 VLA 重规划 150 ms、夹爪闭合 120 ms、伺服余量 80 ms → `T_lead ≈ 0.35 s`；30 Hz 帧间隔 33 ms → `K ≈ 10–11`，与论文 K_max=10 巧合吻合，但**必须用你自己的延迟重算**。
  更稳的做法：直接用**时间**做 horizon（`T_horizon` 秒），而不是 token 步，避免换帧率就失配。
- **传送带速度 → 预测位移**：`d = v_belt · T_lead`。v=0.1/0.2/0.3 m/s 时 d = 3.5/7/10.5 cm。**苹果直径 ~7–8 cm**，所以 0.2 m/s 起"预测误差 = 一个果径"就是必抓空——这就是必须做拦截点而非"追当前位"的定量理由。
- **显著性 mask 简化版**（省掉语言 cross-attn）：`S = {patch : ‖V_i‖ > τ_flow} ∪ ROI_mask`，ROI 由检测框外扩 1 个 patch 得到；`τ_flow` 按论文做法用**空传送带跑 200 帧取 99 分位**标定。196 token 里预计只剩 20–40 个，世界模型算力降一个量级。
- **不确定性早停用于"滚动/易损"品类**：苹果/梨会滚、草莓会滚且易损、香蕉形状不规则。当 `ū > τ_u`（τ_u 取训练集 90 分位）就缩短 horizon 并**降速**——论文明确说"arm speed is not yet gated by prediction variance"，这是你可以补的改进点：`v_max ∝ 1/ū`。
- **剔除机械臂 patch**：单臂 Franka 自运动投影简单（URDF + 手眼外参），照抄即可，论文报 +4.8 点（87.4→92.2）。
- **对齐层别省**：去掉后 Conveyor 97.3→88.4、Ballistic 87.4→61.1。用 `L_align` 直接对"动作误差"监督，只有 0.1M 参数、4 GPU-h。

### C. 模块划分（建议落到 `src/fruitsort/`）

```
perception/flow.py     RAFT 或 cv2.Farneback 的 per-patch V,A（先用轻量的，AHEAD 证明帧差 38.5% 太差、RAFT 93.5% 最好，Farnebäck 68.9% 是可接受的降级）
perception/track.py    多目标 3D 质心跟踪 + 恒加速拟合（Track-and-Intercept 等价物）
predict/intercept.py   可达性约束下求 t*；无解→旁路策略
predict/world_model.py 4 层 encoder + 流匹配 + 自适应早停（可选，二期）
control/timed_grasp.py 时间参数化轨迹 + t*−t_close 闭合 + 方差限速
eval/latency.py        复现 158/171 ms 的分项计时（RAFT / WM / VLA / IO）
```

### D. 数据与评测

- 仿真：ManiSkill3 里搭"传送带 + 4 品类"，速度 0–40 cm/s 分 5 档（对齐论文 sweep），用**特权状态脚本规划器**采 500 条/场景（AHEAD 就是这么造仿真数据的），保证动态任务有足够正样本。
- 真机：**先在静止场景学抓取**（论文的 200 条真机数据全是静态遥操作 + 被动传送带/弹射片段，动态能力完全由预测模块提供）——这对 Fruitsort 是好消息：不必为每个速度段重采数据。
- 评测：每档速度 10 次、5 档共 50 次；记录失败分类（抓空 / 抓晚 / 撞飞 / 掉果）。

## 复现成本与风险

- **算力**：预训练要 8×H100 × 96 GPU-h ≈ **768 GPU-h**。单张 5090（约 H100 的 1/3–1/2）意味着 **2–3 个月**，不可行。**结论：跳过视频预训练，直接在 ~200–500 条本机轨迹上从零训世界模型**，代价是丧失跨域先验（论文报"语料缩到 25% 只掉 2.9 点"，说明数据效率尚可，但 25% 仍是 164K 序列）。
- **显存**：7B OpenVLA bf16 ≈14 GB + RAFT + 世界模型，5090 32 GB 够；但需 OpenVLA 先在本机 Franka/水果数据上微调（另有成本）。
- **sm_120 风险**：OpenVLA 依赖 flash-attn 等，旧 wheel 在 5090 上会 `no kernel image`；必须 torch ≥2.7 + 重编译 flash-attn，属于已知坑。
- **方法本身的失效边界**（论文自述）：
  - 恒加速假设在**碰撞后混沌动力学**下崩（Plinko 48.6%）；苹果从传送带落到料框、草莓相互碰撞就是这类。
  - 光流只有**图像平面**运动，深度方向运动（水果朝相机滚来）会失真；建议加 depth 光流或多视角。
  - 样本方差共享**同一个 RAFT 速度估计**，光流系统性错误时"自信地错"（高光/无纹理表面：苹果打蜡反光、草莓籽、香蕉无纹理段都是高危）。
  - 腕部相机未验证（需用正运动学扣自运动）。
- **工程风险**：论文的 30 Hz + 158 ms 预算是在 H100 上；5090 上要重测，若超过 200 ms，`T_lead` 变长 → 拦截点更靠下游 → 需要更长传送带或更高带速上限下调。
- **不可迁移部分**：论文用平行夹爪 + 刚性物体；草莓易损，需要力控/柔性夹爪，本文完全没涉及抓取力与形变。

## 原文关键片段

1. "Policies that act on the current observation assume the scene is stationary until execution, so at any non-trivial object speed the resulting latency exceeds the time available to grasp."
2. "AHEAD adds 4.9M parameters to a frozen 7B OpenVLA and reaches 79 to 97% success across 20 dynamic simulation scenarios where the strongest baseline reaches 31 to 58%."
3. "To avoid asking the world model to learn full physics from data, AHEAD propagates the velocity conditioning analytically across rollout steps under constant-acceleration kinematics, Vk = V0 + A · k · ∆t."
4. "Baselines without explicit prediction (Retargeting VLA, VLA + Fast Replan, Realtime ACT) most often fail by grasping where the object was rather than where it will be; the gripper closes on empty space behind the moving object."
