# StreamPI：给 VLA 装一条"流式多模态时间轴"

> **arXiv**: [2608.26067v1](https://arxiv.org/abs/2608.26067)（cs.CV，2026-08-26）
> **机构**: The University of Hong Kong（HKU）、ACE Robotics
> **作者**: Zhe Liu*, Jinghua Hou*, Yuxiang Lu, Zhenya Yang, Xianzhe Fan, Junwei Luo, Junyi Li, Ruihua Han, Zhi Hou, Hengshuang Zhao（†通讯）
> **项目页**: https://happinesslz.github.io/projects/StreamPI
> **代码**: 未在正文找到 GitHub/HuggingFace 链接（仅项目页）

## 一句话结论

不新增任何参数，只改**注意力掩码**：把每个 `(多视角图像, 语言指令)` 当成一个"原子时间单元"，单元内双向注意力、单元间因果注意力，再用**随机间隔采样**训练，就能让单帧 π0.5 获得时间记忆与多帧几何感知；真机上"藏杯子（Shell Game）"从 46.7% 提到 80.0%，"滚瓶抓取"从 26.7% 提到 63.3%，而 5 帧只增加 9.2 ms 推理延迟。

## 要解决的问题

单帧 VLA（π0、π0.5）在每个推理步只看一张图，缺两类能力：

1. **时间记忆**：物体被杯子盖住又洗牌后，单帧无法知道东西在哪；"我刚刚是不是已经抓过这个槽位"也无法判断。
2. **空间精度**：单帧缺少运动视差/多视几何，插笔入窄瓶、套杯这类亚厘米任务不稳。
3. **已有的多帧方案有代价**：窗口式（CronusVLA、TriVLA 等）把 K 帧拼进序列 → 序列长度线性增长、延迟高；或换小骨干/额外视频编码器 → 新参数分布与预训练 VLA 不对齐，破坏原有视觉-语言表征。
4. 还有一个隐蔽问题——**指令遗忘**：视觉 token 越堆越多，固定的语言 token 被稀释，长程任务里模型"忘了自己要干什么"。
5. **训练/部署错配**：训练用固定间隔采帧，真机观测是异步、变间隔到达的。

## 方法核心

### 原子时间单元

```
u_t = (V_t, l_t)          # V_t = {前视, 左腕, 右腕}，l_t = 该时刻的语言指令
U   = [u_{t-T+1}, ..., u_t]   # 流式缓冲里最近 T 个单元
```

- **单元内双向注意力**：`h_τ = Attn_bi(V_τ, l_τ)` —— 每个时间步都把指令与图像重新绑定一次，指令永远不会被历史视觉 token 淹没（这是"instruction-anchored"的含义）。
- **单元间因果注意力**：`o_t = Attn_causal(h_{t-T+1}, ..., h_t)` —— 保证不泄漏未来帧，且天然支持在线流式。
- 最终 `a_t ~ π_θ(· | o_t)`。

### 零新增参数

整个结构**只靠重排 attention mask** 实现，位置编码扩展到多帧 token；利用 LLM 骨干的长度外推能力继承 π0.5 全部权重。因此同一个模型可在推理时用 T=1/3/5/8/10 帧（单帧模式即退化为 π0.5）。

### 随机间隔流式训练

- 基础间隔 `δ̄`，每步加扰动 `ε ~ U(-Δ, +Δ)`，得到 `δ = δ̄ + ε`，再 clip 到 `[δ_min, δ_max]`；按 δ 从缓冲里取 T 帧。
- 实现默认 `[δ_min, δ_max] = [3, 7]`（30 FPS 采集下约 100–233 ms），训练 T=3 或 5。
- **时间掩码**：随机取 `k ∈ {0,...,T-1}`，把最早的 k 帧遮掉，模拟流式推理"历史还没攒够"的情形。

### 流式推理与 KV-Cache

```text
t0: 编码 u_t0 → h_t0 → 预测 a_t0 → 把 h_t0 写入 KV-Cache
tn: 只编码新帧 u_tn → h_tn 与 cache 中 {h_t0..h_tn-1} 做 cross-attention
    → 预测 a_tn → 追加 h_tn 到 cache
```

- 复杂度对时间长度**常数**（不需重算历史帧）；代价是 cache 随任务时长增长（论文列为局限，未来做自适应剪枝）。

### 仿真与效率

- **LIBERO** 平均：π0.5 96.9 → StreamPI T=3 **97.5** → T=5 **98.3**（Long 分项 92.4 → 95.0，+2.6）。
- **CALVIN**（ABC→D）平均序列长度：π0.5 4.313 → StreamPI **4.547**（MemoryVLA 4.090）；第 5 个任务成功率 85.0% vs 79.5%。
- **推理延迟**（4090，20 trials，mean±std）：T=1 **94.4±3.4 ms**；T=3 97.9±5.1；T=5 **103.6±6.3**；T=8 110.9±10.2；T=10 117.9±16.5 → 5 帧仅 +9.2 ms。
- **消融**（LIBERO 平均）：
  - 单元内双向 → 因果：T=5 时 98.3 → 95.5（Long 掉 5.6），证明"指令锚定"不是可有可无；
  - 去掉单元间注意力（T=1）：98.3 → 96.5（Long −3.0）；
  - 固定间隔 δ=1 训练：T=5 时 97.0 → 随机间隔 **98.3**；T=3 时 96.4 → 97.5；
  - 跨帧数泛化：T=5 训练的模型在 T=3 略降、T=1 明显降但仍优于 π0.5。

## 对 Fruitsort 的可执行建议（传送带 / 单 Franka）

**它能给我们什么**：不是降延迟，而是**在同样延迟下拿到运动信息与任务记忆**。对传送带分拣，这解决三件具体事：(a) 从两帧间位移估果子速度（不必依赖光流网络）；(b) 记住"这个位置已经抓过/漏过"，避免机械臂反复扑同一个空位；(c) 多帧几何让草莓蒂、香蕉柄的抓取点更准。

**模块划分**

1. `frame_buffer`：三路相机（前视 + 腕部）各自维护 ring buffer，存 `(frame, ts, instruction_id)`；**按时间戳对齐**，不假设固定帧率。
2. `streampi_policy`：π0.5 骨干 + 自定义 block-causal mask；`instruction_id` 变化时刷新"锚"（换果种/换指令要重置，不然旧指令会一直锚定）。
3. `kv_cache_mgr`：每路相机一份 cache；**抓取完成/切换目标时清空**，否则历史会污染下一颗果子。
4. `scheduler`：以 δ 帧为间隔触发推理，与执行器解耦（异步）；主循环按最新动作执行。

**参数初值**

- T=5，δ=3（30 FPS 相机 → 约 100 ms 历史窗，覆盖 0.4 s）；训练时 δ~U[2,5]（对应 66–166 ms），比论文的 [3,7] 更偏短，因为传送带速度变化快、太长历史反而"过期"。
- 输入：`"pick the {apple|strawberry|banana|pear} on the conveyor and place it in bin {k}"`，**每帧重复同一句**（这是方法成立的前提，不要只在首帧给指令）。
- 动作空间：Franka 7 维 ΔEE + 夹爪，H=16；控制 30 Hz。注意 StreamPI 本身不改动作头，**可与 FASTER 的 HAS 采样、或 DiscreteRTC 的离散头叠加**。
- 记忆增强用法：把"已抓取槽位/已扫描区域"编码进指令文本（`"... skip bins 1-3"`），利用指令锚定机制让策略持续看到状态，比外挂状态机更稳。
- 果种差异：
  - **草莓**：T=5、δ=2（更密），因为果小、易被叶遮挡，多帧视差最有价值；
  - **香蕉**：T=3 即可（大目标、运动慢），把预算留给更高控制频率；
  - **苹果/梨**：T=5，重点用帧间位移估滚动方向（滚动会让抓取点偏移）。
- 评测：除成功率外，单独测"遮挡后重定位成功率"与"重复抓空率"——这是 StreamPI 的强项指标，能直接量化收益。


### 三种范式对照（论文 Fig.1 的论断）

| 范式 | 时间记忆 | 3D/几何感知 | 计算量 | 指令保持 |
| --- | --- | --- | --- | --- |
| 单帧 VLA（π0.5） | 无 | 弱（单视角） | 1× | 好 |
| 窗口式（K 帧拼接） | 有 | 较强 | ≈K×（序列线性增长） | **差**（视觉 token 稀释指令） |
| StreamPI（流式 + KV cache） | 有 | 较强 | ≈1×（每步只编码新帧） | **好**（每帧重新绑定指令） |

### attention mask 到底长什么样（实现要点）

```text
# 序列布局： [v_1 l_1][v_2 l_2] ... [v_T l_T]  + action tokens
# 1) 单元内（i 与 j 同属一个 t）：全 1，双向
# 2) 单元间（t_i < t_j）：允许 j 看 i（因果），禁止 i 看 j
# 3) action token：可看全部历史单元（它是"当前决策"）
mask[i, j] = 1 if (unit(i) == unit(j)) else (unit(i) >= unit(j))
```

- 位置编码：给每个 token 加 `(frame_index, token_in_frame)` 两级编码，或直接按展开序号线性外推；**不要**让不同帧共用同一组位置 id，否则帧序信息丢失。
- 训练采样：从 buffer 里按随机 δ 取 T 帧后，仍要保证 **最后一帧是当前帧**（否则动作与观测错位）。

### 放到传送带上的时序预算（估算，非论文数字）

- 相机 30 FPS、δ=3 → 历史覆盖约 0.1 s；若传送带 0.2 m/s，两帧间果子移动 20 mm，正好是可测的速度量级（像素位移足够大，又不会跨出视野）。
- 若相机降到 15 FPS，δ 必须改成 2（≈133 ms）才能保持同样的物理时间跨度——**δ 应按"秒"标定，不该按"帧"硬编码**。

## 复现成本与风险

- **算力**：π0.5 全量微调，8×H100、batch 128、50k iter（真机）。我们单卡 5090 只能 LoRA 或小 batch；更现实的是**在已有 π0.5 LoRA 权重上继续用随机间隔训练 3–5k 步**。
- **实现成本**：无新参数，但要改 attention mask + 位置编码 + 数据加载器（按时间戳采样），属于"中等改动、易出 silent bug"的一类；建议先写单元测试验证"帧 t 的 token 看不到 t+1"。
- **主要风险**：
  1. **KV-cache 与异步观测冲突**：相机掉帧/乱序会让 cache 的时间顺序错乱，必须有时间戳排序与超时丢弃。
  2. **训练成本随 T 线性增长**（论文自述局限）；T>10 不划算。
  3. **延迟不是它解决的问题**：94→104 ms 的绝对延迟对高速传送带仍偏大，必须与 FASTER/DiscreteRTC 组合。
  4. **无代码**：只有项目页，复现要自己实现 mask 与数据管线；π0.5 本身也要 openpi 栈。
  5. **未明确**：动作维度、控制频率、Franka 类单臂验证均未给；真机数字均来自 PiperX 双臂平台，样本量 15 trials/任务，置信区间较宽。
