# PhysMani: Physics-principled 3D World Model for Dynamic Object Manipulation

> **arXiv** 2607.01938v1（cs.RO，2026-07-02；ECCV 2026）· **机构** vLAR Group，香港理工大学 + Astribot
> **代码** https://github.com/vLAR-group/PhysMani · **数据/权重** https://huggingface.co/datasets/vLAR/PhysMani-Bench
> **项目页** 未在正文找到（论文只给 GitHub 链接）
> 标签 #3DGS #world-model #velocity-field #3DFA #benchmark

## 一句话结论

把"未来"表示成 **3D Gaussian 的无散度速度场**（每帧在线优化 ~200 ms，无需离线训练世界模型），再把每个场景点的 K 近邻高斯速度用"一个可学习 query token"注入 3D 策略——平均成功率 45.9%（3DFA 37.8%），真机传送带/转台 62.5%（3DFA 45.3%）。最值得抄的是**注入方式**（KNN + 相对偏移 + 速度 + learnable query 的 3 层 cross-attn），不是 3DGS 本身。

## 要解决的问题

- 现有 VLA / 视频世界模型三点不足：(1) 表征缺乏显式 3D 几何；(2) 生成帧"看着真"但常违反物理（引用 Motamed et al. 2026）；(3) 链路式大模型延迟高，动态任务不可用。
- 早期动态操作工作只覆盖单一场景（乒乓、足球、传送带抓取），缺通用框架。
- 缺动态操作 benchmark：现有 RLBench/LIBERO/CALVIN 都是静态/准静态。
- FreeGave（他们直接改的前作）依赖独立形变网络 + 离线优化，不能在线跑。

## 方法核心

### 1 canonical 3D Gaussian（t=0 建场景）

- C 个已知位姿的 RGB-D，稀疏点云反投影初始化 **25,000** 个高斯：`s_0=[0.04,0.04,0.04]`、`r_0=[0,0,0,1]`、`σ=1.0`。
- 3,500 iter 优化，每次随机采 1 个视角，损失：

```
ℓ = (1-λ_ssim)·ℓ1(I,Î) + λ_ssim·(1-ℓ_ssim) + (1-λ_ssim)·ℓ1(D,D̂) + λ_ssim·(1-ℓ_ssim(D,D̂)),  λ_ssim=0.2
```

- RTX 4090 上约 **15 s**（每个场景）。

### 2 物理先验的速度场（核心创新）

每个高斯用 MLP `f_vel` 学 6 个基速度分量：

```
V_t = f_vel(g_0, t) ∈ R^{1×6} = [v_x, v_y, v_z, w_z, w_y, w_x]     # 3 线速度 + 3 角速度
v(g_t, t) = V_t · B(g_t)
B(g_t) = [[1,0,0,-g_y, g_z, 0],
          [0,1,0, g_x, 0,-g_z],
          [0,0,1, 0,-g_x, g_y]]ᵀ      # 6×3，含坐标项
```

这个基的作用是**保证 ∇·v = 0（无散度/不可压缩）**，即"刚体整体平移+旋转"这一类合法运动，从而避免高斯"凭空生成/消失"。`f_vel` 是 FreeGave 的两段 MLP（f_code 51→128 →16 维，f_weight 14→64→16），最终 `f = f(g_0)·f(t)` 输出 6 维。

### 3 在线优化（Algorithm 1，无训练、纯 test-time 优化）

每来新帧 `{I_t^c, D_t^c}`：

1. 用当前 `v(g_t,t)` 把高斯从 t′ 积分到 t（FreeGave 的 interleaved midpoint）；
2. 用 ℓ1+ℓ_ssim 优化 **T=50** iter，更新 `g_t, r_t, f_vel`（学到速度场）；
3. 冻结 `f_vel`，再优化 **T′=7** iter 精修高斯属性（补几何/外观微变）。
4. 输出每个高斯的 6 维速度 `V_t`。

耗时：**~200 ms/轮**（4090）。**CUDA Graph 复用静态图**（高斯数固定 ⇒ 图固定）：`cudaLaunchKernel` 67,330 → 9,118，440 ms → **198 ms**（>2×）。

### 4 未来动力学如何进入策略

- 场景共 `H = 30,000` 个高斯，动力学 `D_t ∈ R^{H×6}`。
- 策略骨干 = **3DFA**（3D Diffuser Actor 把 DDPM 换成 Rectified Flow，架构不动）：
  - 当前 RGB-D → 稀疏点云 `P_t ∈ R^{4096×3}` → 视觉 token `F_t^vis ∈ R^{4096×120}`；语言 53 token；cross-attn 融合 → `F̃_t^vis`。
- 注入（6 步）：
  1. 每个点 `p_t` 用 KNN 找 K 个最近高斯（K 值正文未给）；
  2. 相对偏移 `Δp = p_t - g_t^k`；
  3. 全点云批量得到 `ΔP ∈ R^{4096×K×3}` 与 `D̂_t ∈ R^{4096×K×6}`；
  4. 两个 MLP 各自映射到 120 维；
  5. **可学习 query 向量 `L ∈ R^{1×120}`**，`ΔP̄` 作 key、`D̄` 作 value，3 个 cross-attn block → `D̃_t ∈ R^{4096×120}`；
  6. `A_t = F̃_t^vis + D̃_t`，作为动作预测的输入。
- 动作：末端 keypose `a = {pos∈R³, rot∈R⁶, open∈{0,1}}`，预测 horizon J 的轨迹；10 步 rectified flow 去噪；损失

```
ℓ = ℓ2( V_flow(A, o, l, τ^i, i), (ε - τ⁰) ) + BCE( f_open(...), a_open )
```

- 真机执行：keypose → IK → 关节轨迹；**5 Hz 控制 + 动作缓冲 + temporal ensemble**（推理与执行解耦）。

## 世界模型三问（按任务清单）

- **物体运动怎么表示**：**每个 3D 高斯的 6 维速度（3 线 + 3 角）**，全局无散度约束。没有物体实例、没有类别、没有 contact 模型——纯几何+运动学。
- **未来帧怎么预测**：不需要逐帧自回归生成网络 ⇒ 沿速度场积分 + 渲染。评估时渲染未来 10 步（50 ms/步 ⇒ 到 500 ms）。
- **推理速度**：世界模型 198–205 ms/帧；策略 272.8 ms/keyframe；系统整体 5 Hz（靠缓冲解耦）。
- **是否需要大规模预训练**：**世界模型不需要**（test-time 在线优化，这是全文最诱人的一点）；**策略需要**（3DFA 预训练 100k + 微调 100k，但只有 ~1 GB 推理显存，比 5B 级 WAM 轻 1–2 个数量级）。

## 对 Fruitsort 的可执行建议（单 Franka + 传送带，苹果/草莓/香蕉/梨）

### 完全可以经典化的部分（建议第一版就这么干）

1. **世界模型 → 卡尔曼 + 深度**：传送带上水果是匀速直线（= 无散度速度场的平凡解）。用外部 D435i 的 RGB-D 做 3D 检测（YOLO/阈值 + 深度反投影），每类一个匀速卡尔曼，直接得到 3D 位置 + 速度 ⇒ 与 `D_t`（位置+6 维速度）**接口等价**，成本几乎为零。论文用 200 ms/帧在线优化 30k 高斯去恢复"匀速"，对我们纯属浪费。
2. **3DGS 可以整段跳过**：我们的场景背景固定、物体是已知刚体、相机外参可标定。3DGS 的价值在"未知复杂几何 + 多视角重建"，不是我们的痛点。
3. **未来预测 → 常速外推 + 抓取窗口**：`p̂(t+k) = p + v·k·dt`，再解析求拦截点（含夹爪闭合延迟）。论文的 Traj.Err 0.008 m@50 ms 就是匀速假设的性能量级。
4. **策略可先用几何伺服**：末端朝向对准质心 + 深度对齐 + 定时闭合，不需要学习。先把节拍和工位跑通。

### 值得学的地方（按性价比）

1. **注入接口照抄，内容换成经典量**：`ΔP`（点到物体中心/表面的相对偏移）+ `D̂`（速度）+ learnable query 的 3 层 cross-attn ⇒ 一个极小的模块，可以插到任何 3D 策略上。这是本文最干净的贡献，且**消融证明了它有效**（去掉速度 45.4→37.9）。
2. **3DFA 作为策略骨干**：开源（3d_diffuser_actor）、1 GB 推理、Rectified Flow 10 步、输出 keypose + IK。对 5090 非常友好，比 WAM 路线现实得多。适合我们"抓取 + 投放"两类动作。
3. **消融结论直接用**：3DFA-OF（把 2D 光流传进去）**没有任何增益**（37.5 vs 37.8）⇒ 我们不必花时间做 2D flow 特征；要么上 3D 运动量，要么不做。
4. **延迟鲁棒性实验设计**（人为注入 0–300 ms 延迟看 SR 曲线）值得照搬成我们的标准评测项：它直接量化"我的策略能容忍多少推理延迟"。
5. **5 Hz 控制 + temporal ensemble + IK**：低速传送带（0.1–0.3 m/s）下 5 Hz 足够；这给我们一个现实的节拍预算。
6. **PhysMani-Bench 的任务设计**（8 组 × 普通/高速，物体速度对标机械臂上限，脚本专家采集 160 条/任务）可以直接改造成我们的"传送带分拣"评测协议——比 DOMINO 更贴近我们的 sim 环境。

### 不建议照抄

- 30k 高斯 + CUDA Graph 的在线优化管线：收益是"未知场景物理"，代价是 200 ms/帧、4 相机、深度对齐、以及一堆 CUDA 扩展（gsplat / diff-gaussian-rasterization / pytorch3d）在 sm_120 上的编译地狱。
- `f_vel` 的 6 维无散度基：只对"不可压缩刚体运动"成立；草莓被夹爪挤压、香蕉弯折时会失真（论文没测可变形物体）。

### 单臂 / 单相机适配

- 论文 4 相机是 3DGS 重建的硬需求；我们若跳过 3DGS，**1 个外部 D435i（看传送带）+ 1 个腕部**就够（外部算 3D 位置/速度，腕部做末端微调）。
- 论文用 7-DoF 双臂品牌机（Astribot S1），我们 Franka 7-DoF 单臂 + 平行夹爪，动作空间一致（keypose 6D + 开合），迁移无障碍。

## 复现成本与风险

| 项 | 估计/事实 |
| --- | --- |
| 训练硬件 | 3×GPU、bs 18、100k + 100k 迭代、**53 h**、22 GB/GPU（单 5090 32GB 勉强够，时间 ×3） |
| 推理显存 | 1.0 GB（策略）+ 世界模型（30k 高斯，未给具体值，但 4090 上 198 ms 说明不轻） |
| 数据 | PhysMani-Bench 每任务 160 条；真机每任务 180 train/60 val；数据与 checkpoint 均在 HF 公开 |
| 环境 | 官方 Docker + 3 个可安装包（physmani_bench / wm / policy）+ 子模块（RLBench, PyRep, gsplat, pytorch3d, diff-gaussian-rasterization） |
| 代码完整度 | v1.0 重构版：PhysMani + 3DFA baseline 可训可评；3DDA/ManiGaussian/π0.5 baseline **未放出** |

风险：
1. **CUDA 扩展 + sm_120**：`diff-gaussian-rasterization` / `pytorch3d` 在 Blackwell 上编译经常失败；README 只列了 8.0/8.6/8.9 的 arch 值，5090 需要自己试。这是本笔记里最高的一条复现风险。
2. RLBench/PyRep 依赖 CoppeliaSim，Ubuntu 22.04 + 无 sudo 环境下折腾成本不低（我们有 ManiSkill3，可考虑在 ManiSkill3 里重建等价任务）。
3. 论文的 `physmani_bench` 用脚本专家（非人类遥操作），我们的水果形变/滚动特性难以用脚本专家覆盖。
4. 真机只有 4 任务、每任务 64 trials；`Place on Rack` 只有 25%，说明"放到运动目标上"仍是难点（我们的"放进运动中的箱子"同理）。

## 原文关键片段

1. "We propose PhysMani, a framework that couples a physics-principled 3D Gaussian world model with a future-aware action policy model. The world model learns a divergence-free Gaussian velocity field via online optimization for fast and physically grounded future dynamics prediction."
2. "we introduce an online optimization mechanism that efficiently predicts a divergence-free per-Gaussian velocity field, thereby guaranteeing that the anticipated future scene dynamics adhere to fundamental physical laws."
3. "for each 3D Gaussian in the dynamic environment, we attentively incorporate the estimated velocity information from its local spatial neighborhood into the policy network, so that the robot's predicted future actions are explicitly conditioned on the anticipated future motion of dynamic targets."
4. "incorporating CUDA Graph optimization cuts the world model latency by more than half, yielding an over 2× speedup."

## 存疑 / 未说清

- KNN 的 K 值、视觉 token 120 维的来源、点云 4096 点的采样策略都只在 3DFA 原文里，正文没重复。
- 世界模型每帧要 50+7 次迭代、4 视角渲染，但**没报显存与多相机同步要求**；我们单相机时 3DGS 会退化（几何只能靠先验）。
- 只用"位移场"表达运动，无法表示拓扑变化（切开、液体、形变）——水果被夹持变形属于此列。
- 评测是 2 Hz 策略查询（每 10 个 50 ms 步），与真机 5 Hz 不一致；两个设置的结论不能直接互推。
