# TEMPO：动态操作缺的是"时间上下文"，不是模型规模

> **arXiv**: `2609.16864v1` [cs.RO] · 2026-09-15 · **CoRL 2026 (Oral)**
> **机构**: University of California, Irvine（Zhenyang Feng\*, Jimin Heo\*, Erik B. Sudderth, Unnat Jain）
> **项目页**: <https://tempo-robot.github.io/>
> **代码**: <https://github.com/tempo-robot/TEMPO>
> **数据/benchmark**: <https://github.com/tempo-robot/TempoBench>（TEMPO-Bench，>50k 标注帧）

## 一句话结论

把手持瓶子的**拦截抓取**失败拆成两种**表征缺失**——"运动歧义"（单帧没有速度）与"状态混叠"（同一画面在任务不同阶段要相反动作）——并各给一个几乎零成本的外挂输入：`TEMPO_MOT`（冻结视频基础模型出的运动 token）+ `TEMPO_ACT`（把最近 300 步本体命令压成 10 个桶的均值）。**只加 2M 参数（0.08%）**，Bottle Handover 44%→74%，且是唯一能跑通"取-放同位置"混叠任务的系统。结论直接：**先补时间上下文，再谈换大模型或压延迟。**

## 要解决的问题

- 现有 VLA 在准静态任务很强，但**推理时只有一帧**。两个失败模式：
  - **Motion ambiguity（运动歧义）**：一帧只有"配置"没有"演化"。即使延迟降到 0，快照也不含速度。"机器人从走过的人手里接瓶子，必须预测抓取执行时瓶子在哪，而不是观测时在哪。"
  - **State aliasing（状态混叠）**：多阶段任务里，视觉几乎相同的两帧要相反动作（伸手去拿 vs 拿到后收回）。单帧策略会在两者间**犹豫、抖动、不commit**，任务卡死。
- 关键论断：**这两个失败与模型规模、推理延迟无关**（作者用 probe 证明：同 π0.5 主干，RTC/VLASH 的隐状态解不出物体速度，R² ≤ 0.09）。异步推理解决"预测何时被用"，TEMPO 解决"策略被什么条件化"，二者正交。

## 方法核心（含关键公式/伪代码）

### 1. TEMPO_MOT：用冻结视频模型做"运动摘要"

```
滚动缓存 F_t = {f_τ}_{τ=t-W+1}^{t-1}   # 前 W-1 帧的 patch 特征，逐帧增量填充，每帧只算一次
m_t = CrossAttn(query=f_t, key/value=F_t)   # 当前帧特征去 attend 历史特征
```
- `f_τ` 来自 `φ` 的**逐帧编码器**；`φ` 实例化为**冻结的预训练视频基础模型**，off-the-shelf 不微调。
- 默认 **SAM 2.1-Tiny**（选它是因为流式速度：**≈11 ms/帧**，RTX PRO 6000）；备选 Reducio 76%、VidTwin 60%、VideoLaVIT 52%（vs VLASH 基线 38%），**换 encoder 仍稳超基线**。
- 输出 `m_t` 投影到 VLM token 维，**追加到 prefix**（与当前多视角观测、语言指令并列）。

### 2. TEMPO_ACT：本体历史的定长摘要（解决混叠）

- 取最近 H 条本体命令 `q_τ ∈ R^{d_q}`，**等分成 K 个连续时间桶**，桶长 `L = H/K`，从旧到新：
  `c_t = ( q̄_t^(1), …, q̄_t^(K) )`，`q̄_t^(k) = (1/L) Σ_{τ∈B_k} q_τ`。
- 取 **K = 10 桶 × L = 30 条命令 = 300 步历史**；整桶落在 episode 开始之前则打 pad 标记。
- **无论历史多长，永远只有 K 个 token**（延长视界只改 L，不改 token 数）——parameter-free 的降采样，这正是它能"零成本"的原因。
- 两条注入路径：① 投影成 VLM prefix token；② 展平过 MLP 产生 **AdaRMS 残差**，直接调制 action expert 的去噪。**新增条件路径零初始化**，保证微调开始时原策略行为不变。

### 3. 实时部署：后台线程 + 固定窗口

- `TEMPO_MOT` 在**独立后台线程**按传感器帧率跑（≈11 ms/帧），持续更新"最新 motion token"，策略每控制步只读一次。
- 策略侧开销仅 **≈1.5 ms**（35.3 ms vs VLASH 33.8 ms 中位前向）；对比 RTC **127.7 ms**。
- 因为 `φ` 用**固定长度流式窗口**，单帧成本与历史长度无关 → **控制频率不受历史长度影响**。

### 4. 与 UVT 组合（可选）

输入侧（TEMPO）补时间上下文，输出侧（UVT：不回归原始关节块，而回归与物体运动对齐的紧凑运动基元）收紧目标，二者不冗余；TEMPO+UVT 平均 87.2%（TEMPO 单独 76.0%）。

### 四个任务怎么定义（对 Fruitsort 最有参考价值的"拦截"设计）

| 任务 | 定义 | 考察 |
| --- | --- | --- |
| **Bottle Handover** | 人**从任一方向走过**机器人，手中持瓶；机器人须在正确时刻/位置**拦截抓取**，再放到桌上。变化：行走速度、瓶子高度、持握姿态 | P1（运动）→ 抓取**时机** |
| **Drop Catch** | 人**横向移动**的手拿一块魔术贴板交给机器人，机器人先横向**跟手**，再接住落下的球（球从 33–46 cm 高释放，网球大小） | P1+P3（运动+子任务顺序） |
| **Flick Catch** | 5–6 个魔术贴球摆在一段 80×20×21.6 cm 的横台上；人手悬停后**随机时刻**弹飞一颗；机器人先跟手、再切到追球 | P1–P4（最难，含混叠） |
| **Wine Pour** | 机器人拿瓶向**被不断移动的锅**倒珠子；先取瓶 → 边跟锅边倒 → 放回瓶 | P3+P4（取/放同位置 → 混叠）；指标=锅内留存率 |

> 评测防作弊细节值得抄：**人闭眼 + 戴耳机**执行释放，避免人迎合机器人位置而偏置落点。

## 对 Fruitsort 的可执行建议（传送带动态分拣：苹果/草莓/香蕉/梨，单 Franka 臂）

### A. 立刻可上：`TEMPO_ACT` 式本体历史（成本≈0，优先做）

分拣线是**周期性重复动作**：靠近 → 抓 → 抬 → 移到料框 → 松 → 回撤 → 再靠近。这正是 TEMPO 说的**状态混叠重灾区**：
- "回撤后的手在苹果上方"与"第一次来抓苹果"在第三人称画面里几乎一样 → 策略可能**提前闭合**或**犹豫**。
- 实现（parameter-free）：
  ```
  取最近 H=300 条 action/关节命令（30 Hz 下 = 10 s）
  分 K=10 桶，桶长 L=30，逐桶均值 → c_t ∈ R^{10×d_q}
  ① 投影成 prefix token（若用 VLA）
  ② 或用 MLP 出 AdaRMS/FiLM 调制信号（若用 ACT/DP 这类非 LLM 主干 → 直接 FiLM 到观测特征）
  零初始化新增路径
  ```
- 对 Fruitsort 的调整建议：10 s 视界对"每件 2–4 s"的分拣节拍**太长**，建议 **H=90（3 s）、K=6、L=15**；即在节拍内覆盖"上一件→这一件"。若用 VLA 可为每条 token 加 pad 标记（照抄论文）。
- 另一个最直接受益点：**夹爪开合历史**。TEMPO_ACT 的均值桶天然包含夹爪开度趋势 → 能区分"要闭合"与"刚张开"，这是分拣线最常见的误动作。

### B. 运动 token：把"传送带速度"显式喂进去（第二优先）

论文证明单帧位置**解不出速度**（原始位置基线 R²=0.08）。Fruitsort 有更强、更便宜的先验：
1. **廉价版**：直接用 `TEMPO_MOT` 的形态——当前帧 patch 特征 cross-attend 前 W-1 帧缓存。**W 取 3–5 帧**（30 Hz 下 0.1–0.17 s），足够估计带速。
2. **更廉价且更准的工程版**（论文没用但在传送带上是白送的）：编码器/检测框中心随时间的**解析速度**，作为 2 维向量拼进观测。这等价于 AHEAD 的 per-token 速度，但自由度只有 2。
3. **`φ` 选型**：论文默认 SAM 2.1-Tiny 是因为 ≈11 ms/帧的流式速度。**5090 上 SAM2-tiny 更快**，且 `facebookresearch/sam2` 已在 `docs/baselines.md` 登记（⬜ 未试）。建议：后台线程 30 Hz 跑，只更新"最新 motion token"，策略侧只付一次 attend 的成本。
4. **对四种水果的意义**：`TEMPO_MOT` 是 **object-agnostic** 的，苹果（球）、草莓（锥+籽纹理）、香蕉（长条、易滑）、梨（梨形、易滚）**不需要为形状做特化**——这是相比"检测框 + 位姿估计"流水线的核心优势（无需 6D 位姿、无需 CAD 模型）。

### C. 拦截时机：TEMPO 的"跟手—接球"切换 = Fruitsort 的"跟果—闭爪"切换

- Drop Catch / Flick Catch 的课程结构可以直接搬：
  - 阶段 1：**跟踪**（TCP 跟传送带上果子的预测位置，横向速度匹配）
  - 阶段 2：**切换目标**（若同时有多果，切到指定那颗 —— 论文 P2"target shifts"）
  - 阶段 3：**commit**（在 `t* − t_close` 闭爪，一次性动作，不许犹豫）
- 关键设计：**"commit" 必须是一个不可回退的动作**。TEMPO 的失败分析显示，基线最大问题是"每帧都重新发起动作"（VLASH 在 Drop Catch 有 23/50 次 **premature move**，TEMPO 降到 6/50）。→ Fruitsort 应显式建模一个 `grasp_committed` 布尔状态，进入后**锁定目标 ID 与拦截点**，只在偏差超阈值时才放弃（否则抖动会让夹爪反复开合）。
- 用 `TEMPO_ACT` 消 premature move 的机制：历史里已有"我已开始靠近"→ 策略不会每帧重新规划。这在传送带"多果连续通过"时尤其重要。

### D. 对齐 AHEAD 的预测时域（把三篇拼成一条流水线）

建议的模块划分与参数（融合三篇的最优组合）：

```
perception/flow.py        RAFT 或 SAM2-tiny 后台线程 → motion token（TEMPO_MOT 形态）
perception/track.py       多果 3D 质心 + 恒加速拟合（AHEAD 的 Track-and-Intercept）
predict/intercept.py      t* 求解：可达性 + 最小提前量 T_lead = t_replan + t_close + t_servo
policy/                  chunk=8、horizon=1–2、30 Hz 异步（Reflex 的经验最优）
policy/history.py         K=6 桶 × L=15 的本体+夹爪历史（TEMPO_ACT 缩小版）
control/grasp_fsm.py      TRACK → ALIGN → COMMIT(锁定 t*) → LIFT → PLACE → RETRACT
eval/latency.py           延迟注入 + RTF 折算（ReflexBench 协议）
```

- **预测时域**：`T_lead ≈ 0.3–0.4 s`（以本机实测量级估）；带速 0.2 m/s → 前视 6–8 cm ≈ 一个果径 → 必须做拦截而非追踪。
- **状态机**是本文最该抄的"非网络"结构：混叠问题的本质是"阶段未显式化"，用 FSM 或 `TEMPO_ACT` 二者之一即可，**两者叠加最稳**。
- **诊断指标**（照抄论文的 probe）：训练后拿策略隐状态做**线性/MLP probe 预测带速**，`R² < 0.1` 就说明策略"运动盲"，此时换更大模型没用。这个检查半小时能做完，是判断"要不要重训"的最便宜依据。

### E. 训练与数据

- TEMPO 只做**微调**（不预训练），单策略 2 h / 8×RTX PRO 6000 → 单卡 5090 按算力折算约 1–2 天量级（估算，非论文数字）。
- 数据：Fruitsort 无需"人手交接"这种难采数据，可用**脚本 + 遥操作**混合；关键是**必须保留"回撤/放回"段**——TEMPO 的对比之所以惊人（0% vs 68%），正是因为基线数据里保留了混叠段而 TEMPO 能解。**千万别为了让基线好看而把回撤段剪掉**（论文自己承认他们为了做非平凡对比剪了，这是它最被诟病的一点）。
- 评测：仿论文做**失败模式人工归因**（Success / Near Catch / Gripper Miss / Complete Miss）；Fruitsort 版建议 `detect_miss / approach_wrong_spot / premature_close / late_close / slip / wrong_bin`，50 次/配置。

## 复现成本与风险

- **成本低**：2M 参数、零初始化、无新预训练；主要工作在数据管线（多帧缓存、本体历史桶化）与"零初始化 AdaRMS"的实现细节。
- **主干依赖**：论文建在 VLASH（异步推理）之上，且 RTC 无开源代码（作者自己重写）。Fruitsort 若用 LeRobot/ACT/DP 而非 π0.5 家族，`TEMPO_MOT` 的"追加到 VLM prefix"路径要改成 **FiLM/concatenation 到观测特征**，效果未验证（论文只在 VLA 上验证）。
- **任务错配**：四个任务全是**人-机器人交接**（bimanual、人手运动是主要扰动源）。传送带是**确定性匀速运动 + 无人类**，运动估计难度低得多 → **预期收益小于 44→74 这么夸张**，可能只有几个点。真正的收益在**状态混叠**（分拣循环里必然存在）。
- **Bimanual vs 单臂**：论文平台是双臂（一台负责递、一台接？），单 Franka 上"移动目标 + 固定基座"的可达性约束更强，拦截点可能不可达（AHEAD 的接球失败里 5/11 是**关节限位**导致的）。
- **易损品**：草莓/香蕉的抓取力与形变完全未涉及；`TEMPO_ACT` 里夹爪开度均值可能帮你判断"是否已夹住"，但不能替代力控。
- **数据泄漏风险**：TEMPO-Bench 的 50k 帧是这四个任务的标注，**不能**当 Fruitsort 的评测集；但它提供的"逐帧速度回归 + 多选"评测格式可以直接套到自己的数据上。
- **口径问题**：Wine Pour 用"留存率"而非二值成功率，跨任务平均（76.0%）是把百分比混在一起平均，解读要小心。

## 存疑 / 未说清

- 主表（Table 4）用的是**裁剪版**数据（删掉 release-and-retract 段），未裁剪版只在 Table 1 报了两个任务；跨方法比较的可比性受限。
- `TEMPO_MOT` 的窗口 W **正文没有给具体值**（只说"前 W-1 帧"、"trace 16 帧轨迹"出现在项目页分析图里，不等于 W）。复现需自行扫。
- `λ`、学习率、冻结层范围等训练超参未在正文列出（只说零初始化、flow-matching 损失不变）。
- AdaRMS 的具体形式（π0.5 的 action expert 内部）依赖主干实现，跨主干迁移需重写。
- 单臂平台未测；双臂的"另一只手递物"是否提供了额外线索（例如人类手的意图）未拆分。
