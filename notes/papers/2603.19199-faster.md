# FASTER：重新审视实时 Flow VLA 的"反应"能力

> **arXiv**: [2603.19199v3](https://arxiv.org/abs/2603.19199)（cs.RO，2026-05-16）
> **机构**: The University of Hong Kong（HKU）、ACE Robotics
> **作者**: Yuxiang Lu, Zhe Liu, Xianzhe Fan, Zhenya Yang, Jinghua Hou, Junyi Li, Kaixin Ding, Hengshuang Zhao
> **项目页**: https://innovator-zero.github.io/FASTER
> **代码**: 未在正文找到自有仓库；实验用 `Physical-Intelligence/openpi`（π0.5）与 `2toinf/X-VLA` 官方代码微调

## 一句话结论

现有异步推理只优化"轨迹平滑"，忽略了"反应快慢"。作者把**反应时间建模为随机变量**（由 TTFA 与执行视野共同决定），并提出 **Horizon-Aware Schedule（HAS）**：让动作块里越靠前的动作越早"定型"，第一个动作一步采样即可下发（TTFA 压缩到 `Δt_VLM + 1×Δt_AE`），配合逐动作流式下发 + early-stop，把 π0.5 的 TTFA 从 80.0 ms 降到 62.1 ms、X-VLA 从 113.7 ms 降到 44.8 ms（RTX 4090），乒乓球任务得分 0.80 vs 最优基线 0.53。

## 要解决的问题

1. **同步执行的 chunk 间隙**：必须等整段推理完成才能动，机器人停、世界不停。
2. **异步只解决了"平滑"，没解决"反应"**：RTC / training-time RTC / VLASH 等让 chunk 衔接平滑，但**感知—执行延迟仍在**；外部事件发生时，系统要等下一个推理周期才可能响应。
3. **常数时间表的浪费**：flow VLA 对 chunk 内每个动作都用相同的采样步数（如 N=10），于是"最紧急的第一个动作"被迫和"最远的第 H 个动作"一起等完整去噪 → 这是反应延迟的主瓶颈。
4. 作者用一个先导实验证明：**chunk 前 1–10 帧的去噪路径更"直"**（straightness 更小）、中间估计 `Ã^{τ→0}` 方差更小 → 早期动作本就不需要那么多步。

## 方法核心

### 反应时间的定量模型（§2）

定义：控制周期 `Δt_ctrl = 1/f`；推理延迟 `Δt_infer`；离散延迟 `d = ⌊Δt_infer/Δt_ctrl⌋`；执行时长 `Δt_exec = s·Δt_ctrl`。

| 模式 | 推理间隔 | 反应时间分布 | 期望 |
| --- | --- | --- | --- |
| 同步 | `Δt_infer + Δt_exec` | `U(Δt_infer, 2Δt_infer + Δt_exec)` | `1.5Δt_infer + 0.5Δt_exec` |
| 异步 | `Δt_exec` | `U(Δt_infer, Δt_infer + Δt_exec)` | `Δt_infer + 0.5Δt_exec` |

两个反直觉结论：

- 同步→异步只把期望反应时间降了 `0.5·Δt_infer`，**收益有限**；
- 真正有效的是**同时**降 `Δt_infer`（尤其 TTFA）和提推理频率（减小 s，下界 `s_min = ⌈Δt_infer/Δt_ctrl⌉`）。

### 新指标 TTFA

`TTFA ≈ Δt_VLM + N·Δt_AE`（常数时间表）。机器人不需要整段 chunk 才能开始动，所以 **Time to First Action** 才是反应速度的真瓶颈（类比 LLM 的 TTFT）。

### Horizon-Aware Schedule（HAS）

- 令 flow 时间步**与动作索引相关**：`τ = {τ_i}`，`i∈[0,H-1]`；全局采样进度 `ρ_j` 仍从 1 到 0。
- 每个动作有各自的"定型时刻"（hit time）：
  `u_i = (1 - (i/(H-1))^α) · u_0`，`i∈[1,H-1]`
- 局部时间步：
  `τ_i^j = max(0, (ρ_j - u_i)/(1 - u_i))`
- 取 `u_0 = (N-1)/N`，则 `ρ` 第一次下降时 `τ_0` 已到 0 → **第一个动作 1 步即可下发**；随 `ρ` 继续下降，后续动作依次定型。
- `α∈(0,1]` 控制衰减形状：`α=1` 线性；`α<1` 早期动作更快定型、后期动作拿到更多步数（对应 straightness 曲线）。

### 混合调度微调（关键工程技巧）

直接用 HAS 微调有两个问题：(1) 预训练是常数调度，切换会放大分布漂移；(2) 随机 `ρ~U(0,1)` 时近端动作的 `τ_i` 经常为 0，输入一直是 GT，学不到东西。解法：

- 以概率 `p` 用 HAS，`1-p` 用原常数调度（+ action conditioning）；
- 训练时随机前缀长度 `d ~ U{0, d_max}`，前缀 `τ_i ≡ 0` 并做 loss mask `m_i = 1(i≥d)`，只在后缀算 loss；
- 带前缀的 hit time 加索引偏移：
  `u_i = (1 - ((i-d)/max(H-1-d,1))^α) · u_d`，`i∈[d+1,H-1]`，`u_d=(N-1)/N`。

训练伪代码（论文 Alg.1 精简）：

```text
sample obs, GT chunk Â, noise ε, ρ~U(0,1), d~U{0,dmax}, z~Bernoulli(p)
m = [i>=d]
if z==1:  u = (1-((i-d)/max(H-1-d,1))^α)·u_d ;  τ_i = 0 if i<d else max(0,(ρ-u_i)/(1-u_i))
else:     τ_i = 0 if i<d else ρ
A^τ = τ⊙ε + (1-τ)⊙Â
loss = || m⊙(v_θ(o,A^τ,τ) - (ε-Â)) ||² / ||m||₁
```

### 流式 client-server（把"逐步定型"变成"逐步下发"）

- 服务端：动作 `i` 一旦 `τ_i^{j+1}=0` 且未发送，立刻打包发给客户端；
- 客户端：收到即入队，队列不断流即可（要求"取动作速率 > 控制频率"）；
- early-stop：执行视野 `[d, d+s)` 内动作全部定型就跳出采样循环，剩余步数省掉 → `s_min` 可以更小。

推理伪代码（论文 Alg.2 精简）：

```text
init A~N(0,I); compute u_i
forward VLM(o)
for j in 1..N:
    ρ_j = (N-j+1)/N ; τ^j, τ^{j+1}
    A[0:d] = prefix                     # 覆盖为上一 chunk 的重叠段
    v = AE(o, A, τ^j);  A += v⊙(τ^{j+1}-τ^j)
    for i where τ_i^{j+1}==0 and not streamed: send(a_i)
    if all finalized in [d, d+s): break
```

## 关键实验数字

### 反应速度（机器人控制 30 Hz，`Δt_ctrl=33.3 ms`）

| 模型 | 方法 | TTFA (4090) | s_min (4090) | E[Δt_react] (4090) | TTFA (4060) | s_min (4060) | E[Δt_react] (4060) |
| --- | --- | --- | --- | --- | --- | --- | --- |
| π0.5 | Sync | 80.0±1.6 ms | 3 | 170.0 ms | 303.3±0.8 ms | 10 | 621.6 ms |
| π0.5 | Async | 80.0 ms | 3 | 130.0 ms | 303.3 ms | 10 | 470.0 ms |
| π0.5 | **FASTER** | **62.1±3.1 ms**（1.29×） | 3 | **112.1 ms** | **238.6±1.9 ms**（1.27×） | **8** | **371.9 ms** |
| X-VLA | Async | 113.7 ms | 4 | 180.4 ms | 399.5 ms | 12 | 599.5 ms |
| X-VLA | **FASTER** | **44.8±0.3 ms**（2.54×） | **2** | **78.1 ms** | **129.2±2.4 ms**（3.09×） | **6** | **229.2 ms** |

- 首动作采样步数：10 → 1（"10× faster sampling"）。X-VLA 在 4090 上反应时间上界 111.5 ms < 基线 113.7 ms 下界 → **随机占优**（概率表：vs Async 胜率 1.00）。
- 流式实测（4090，π0.5）：第 1/2/3 个动作分别在 62.1/70.2/77.1 ms 到达，而控制器需求时刻是 66.7/100.0/133.3 ms → **始终提前**。

| 项目 | 设置 |
| --- | --- |
| 平台 | **AgileX Cobot Magic**（Mobile Aloha 风格），**4× 6-DoF Piper 臂**（2 leader 遥操作 + 2 follower 执行） |
| 相机 | 1× RealSense D455 前视 + 2× D435 腕部 |

- **乒乓球**（6-DoF Piper + 球拍，15 trials，0/0.5/1 分制）：RTX 4090 上 FASTER **0.800** vs Training-time RTC 0.533 vs Naive Async 0.200 vs Sync 0.000；RTX 4060 上 **0.467** vs 0.300 / 0.200 / 0.000（Table 8，96% bootstrap CI）。

## 对 Fruitsort 的可执行建议（传送带 / 单 Franka）

**为什么这篇最适合我们先落地**：不改结构、不加参数，只改采样调度和下发方式，可以直接套在已有的 π0.5 / openpi 权重上；对"传送带果子会跑出抓取窗口"这类问题，收益直接体现在 TTFA。

**模块划分**

1. `vla_server`（Python，GPU）：openpi/π0.5 权重 + HAS 采样器（把 Euler 循环改成"逐动作 τ_i"）；暴露 gRPC/websocket。
2. `stream_client`（C++/Python，ROS 2）：收到单动作即写入 ring buffer；`franka_hardware` 以 1 kHz 内环、**30 Hz 外环**消费；buffer 低于阈值报警。
3. `belt_state`：传送带编码器或视觉测速 → 提供 `v_belt`；用于把"目标未来位置"喂给策略，也可用于安全检查（预判是否已越界）。
4. `metrics`：记录每次 `obs_ts → first_action_ts`（TTFA）与 `obs_ts → contact_ts`，离线出分布。

**参数初值**

- 控制：Franka 外环 **30 Hz**（`Δt_ctrl=33.3 ms`），关节插值到 **150 Hz** 下发（对应论文 5× 插值的思路，但内环用 libfranka 的 1 kHz 平滑）。
- H=30（不是 50）：传送带抓取通常 1 s 内结束，短 chunk 让"后期动作"不至于全浪费；s 取 `s_min = ⌈Δt_infer/Δt_ctrl⌉`。
- `N=10`，`u_0=0.9`，`α=0.6`，`p=0.5`，`d_max=10`（论文默认，未见任务特异调参）。
- 预估：若我们的 π0.5 级模型在 5090 上 TTFA≈60–80 ms，则 `d≈2–3`，`s_min=3`，`E[Δt_react] ≈ Δt_infer + 0.5·s·33 ms ≈ 110–130 ms`。传送带 0.15 m/s 时对应 **17–20 mm** 位移——把抓取点前置这个量，或要求策略输出"拦截点"而不是"当前点"。
- **风险控制**：把 `α` 保持 0.6、`p=0.5` 做混合微调，否则长程精度会掉（论文 LIBERO/CALVIN 的小幅下降即来自纯 HAS）。

**建议的消融顺序（省时间）**

1. 只上流式下发 + early-stop（不改训练）→ 测 TTFA 与实际丢果率；
2. 再加 HAS 推理（不微调）→ 看是否抖动；
3. 最后做混合调度微调（p=0.5）→ 对比成功率。

**与 DiscreteRTC 的关系**：两者正交。若我们最终选离散扩散头，HAS 的"按索引给 τ"思想可退化为"按索引决定 unmask 顺序"（正好补上 DiscreteRTC 附录指出的 max-confidence 不按时间顺序的缺陷）。

## 复现成本与风险

- **训练成本**：π0.5 在 8×A800 上 1–2 天；单卡 5090 需 LoRA + 更小 batch，或直接复用社区 π0.5/LIBERO 微调权重再混 Schedule 微调。
- **实现成本低**：采样器改动约百行；流式接口需要一个非阻塞 websocket/gRPC 客户端 + ring buffer，ROS 2 里可用 `rclcpp` 定时器实现。
- **主要风险**：
  1. **量化误差**：HAS 让近端动作只走 1 步，若模型未用混合调度微调，首动作噪声大 → 一定先做第 3 步微调，否则抓取会"抖一下再回正"。
  2. **s 太小导致频繁推理**：GPU 争用（相机、分割、检测同卡）会让 `Δt_infer` 抖动，`s_min` 需按 P95 延迟而非均值设定。
  3. **动作表征**：论文用绝对 EE6D，我们若用 Δ 位姿，前缀覆盖逻辑要检查坐标系（基座系 vs 工具系）。
  4. **未明确**：论文没有报告 Franka/单臂传送带场景；Kinetix 是通用控制任务，迁移性需自测。
