# DiscreteRTC：离散扩散策略是天然的异步执行器

> **arXiv**: [2604.25050v3](https://arxiv.org/abs/2604.25050)（cs.RO，2026-06-03）
> **机构**: UC Berkeley、UIUC、UT Austin、UCLA
> **作者**: Pengcheng Wang, Kaiwen Hong, Chensheng Peng, Katherine Driggs-Campbell, Masayoshi Tomizuka, Chenfeng Xu, Chen Tang
> **代码/项目页**: 未在正文找到（摘要仅写 "More visualizations are on our website"，未给 URL；实验基于 RTC 官方代码库与 StarVLA）

## 一句话结论

把动作头从 flow-matching 换成**离散扩散（masked token + 迭代 unmask）**后，"实时分块（RTC）"所需的 inpainting 就是策略的原生预训练任务——冻结上一段动作的尾部当已解掩码前缀、直接前向即可，无需微调、无需 ΠGDM 引导、推理反而只要约 **0.7×** 算力（flow RTC 要 **1.7×**）。

## 要解决的问题

1. **同步执行的结构性缺陷**：action chunk 之间必须停下来等推理，机器人在"思考"时世界仍在动。对传送带/拦截类任务，这个停顿是致命的，不是靠"推理更快"能消除的。
2. **朴素异步的断裂**：新 chunk 一到就切换 → chunk 边界抖动；temporal ensembling 会把不同模式平均掉；BID 用拒绝采样，算力开销大。
3. **RTC 与 flow-matching 不匹配**（论文的核心批判，四个具体缺陷）：
   - (a) **预训练不含 inpainting**：训练时整段 chunk 同一噪声等级 τ，推理时却要面对"前缀 τ=0、中间插值、尾部 τ=1"的混合噪声，预训练规模再大也不会直接提升异步性能；
   - (b) **必须微调**：要获得 inpainting 能力需专门 fine-tune（action-suffix conditioning 等），对大 VLA 昂贵且有损基座能力；
   - (c) **启发式引导**：ΠGDM 的软掩码权重 W 是手写指数衰减，跨场景固定，需要调；
   - (d) **额外推理开销**：每步去噪都要算 vector-Jacobian product，约 2× 计算，讽刺地拉长了它本想隐藏的延迟。

## 方法核心

### 背景公式

- Flow-matching 动作块：`A_t = (a_t, ..., a_{t+H-1})`，从噪声 `A^0 ~ N(0,I)` 积分速度场：
  `A^{τ+1/n} = A^τ + (1/n)·v_π(A^τ, o_t, τ)`，n 为步数。
- RTC 的 inpainting：若推理延迟为 d 步，新 chunk 的前 d 个动作被冻结为上一 chunk 的值，其余要与该前缀一致。flow 版通过 ΠGDM 加梯度修正：
  `g = (Y - f̂_{A^1}(A^τ)) · diag(W) · (∂f̂_{A^1}/∂A'|_{A^τ})^T`，W 对前 d 个为 1、重叠区指数衰减、末尾 s 个为 0。机器人每 s 步发起一次推理，执行最近结果的下 s 个动作。

### 离散扩散策略

- 用 VQ-VAE / FAST / k-bin 量化把连续动作变成离散 token 序列；前向过程按 schedule 把 token 替换成 `[MASK]`；反向过程迭代 unmask。
- 一个策略含两部分：`p_π` 预测每个位置的 token 分布，`f_π` 决定这一步解掩码哪些位置：
  `A^{k+1}_t = π(A^k_t, o_t) = f_π(p_π(A^k_t, o_t))`。
- 训练目标就是"给随机掩码序列，还原完整动作 token 序列"——**这本身就是 inpainting**。

### DiscreteRTC 的三步机制（伪代码）

```text
# 部署循环；H=chunk 长度, s=执行视野, d=推理延迟(控制步), 控制周期 Δt
loop:
    # 1) 构造输入：把上一 chunk 的 [s, s+d) 段作为"已解掩码"前缀 token 直接放置
    tokens[0:d] = last_chunk[s : s+d]        # 冻结，不参与采样
    tokens[d:H] = MASK
    # 2) 原生前向即 inpaint（无梯度修正、无 W 权重）
    for k in 1..K:
        logits = policy(tokens, obs)          # 一次普通 forward
        unmask 高置信 token（或固定步数）
        if 执行视野 [d, d+s) 内 token 全部解掩码: break   # early-exit
    # 3) 执行，保留部分掩码模式作为下一次的"自然引导"
    execute(tokens[d : d+s]); last_chunk = tokens
```

三个直接推论：

1. **Inpainting = 预训练**：无需额外 loss / 代码（论文称 "0 lines of additional code"）。
2. **自然引导**：离散 token 一旦解掩码就是有语义的合法动作，可在中间状态**提前退出**；剩下的掩码比例自然成为下一次推理的自适应引导强度，替代手写 W。
3. **算力更低**：只需解掩码约 `s/H`（或至少 `1 - d/H`）的 token；也可固定步数、减少每步解掩码数，得到更细粒度动作而总算力不变。

## 关键实验数字

### 仿真：Kinetix（12 个动态任务）

| 项目 | 设置 |
| --- | --- |
| 环境 | Kinetix-Symbolic-Continuous-v1 (large)，物理 60 Hz + frame skip 2 → **30 Hz 控制** |
| 动作 | 归一化 [-1,1]，采集与评测都加高斯噪声 std 0.1（迫使闭环修正） |
| 策略 | MLPMixer + AdaLN，4 层，H=8，channel 256；离散头 **512 bins**、embedding 128 |
| 训练 | 32 epochs，batch 512，AdamW；离散头 CE + L1(λ=0.1)，cosine mask schedule |
| 评测 | 5 步去噪/unmask，延迟 d∈{0,1,2,3,4}，s=max(1,d)，每点 2048 trials |

- DiscreteRTC 在**所有延迟档**上 solve rate 与 throughput 均优于 ContinuousRTC / BID / Naive（图 4）。
- 迭代步数显著少于 ContinuousRTC，延迟越大差距越大（图 5 左）。
- 消融：显式做"前缀解掩码"微调（DiscreteRTC-FT）在 12 个关卡、所有延迟上**一致掉点**（图 9），支持"fine-tuning free"主张；`DiscreteRTC + Fixed Steps` 更好；叠加 VLASH 在大延迟更稳、小延迟略降。

### 真机：UR5e + Robotiq（单臂，腕部鱼眼 RGB）

| 项目 | 设置 |
| --- | --- |
| 机器人 | **UR5e + Robotiq 夹爪 + 腕部 RGB**，FastUMI 采集 500 Hz |
| 动作空间 | 10 维 `[Δx, Δy, Δz, rot6d(6), gripper]`，平移 min-max 归一化，夹爪二值 |
| 模型 | Qwen2.5-VL-3B-Instruct + 36 层 layerwise cross-attention DiT（32 future vision tokens） |
| 离散头 | **256 bins/维 → 16×10=160 token**，8 步 MaskGIT unmask（decode T=0.0, choice T=0.1） |
| 控制频率 | Pick&Place：**20 Hz 闭环 + 5× 线性插值 → 100 Hz 伺服**；Hockey：**50 Hz + 2× → 100 Hz** |
| RTC 参数 | Pick&Place d=4, s=4；Hockey d=7, s=7（flow 版 d=s=5 / 9） |
| 任务 | Dynamic Pick、Dynamic Place（转台 15/20 rpm）、Hockey Defend（高速来球防守） |

- 同步基线在三个任务上 **0%** 成功率（证实异步是必需而非优化）。
- 相对 flow RTC：Hockey Defend **+65%** 成功率，Dynamic Pick 差距同样很大；相对 training-time flow RTC：**+30%**。
- 推理时间：DiscreteRTC **≈0.7×**（相对从零生成），ContinuousRTC **≈1.7×**。
- 单卡 RTX 4090 部署；训练 8×RTX Pro 6000 + DeepSpeed ZeRO-2。


### 离散 vs 连续：逐项对照（论文 §3 vs §4）

| 维度 | Flow-matching + RTC | 离散扩散 + DiscreteRTC |
| --- | --- | --- |
| 预训练是否含 inpainting | 否（整段同一 τ） | 是（随机掩码重建） |
| 推理时前缀处理 | ΠGDM 梯度修正 + 手写 W | 直接放置已解掩码 token |
| 是否需专门微调 | 需要（action-suffix conditioning） | 不需要（实测微调反而掉点） |
| 引导信号 | 固定指数衰减 schedule | 上次遗留的掩码比例（自适应） |
| 单次推理算力 | ≈1.7× | ≈0.7× |
| 中途能否提前停 | 否（τ 未到 0 动作不可执行） | 能（已解掩码 token 即可执行） |

### 实现上的两个坑（论文未强调，但会影响我们）

- **token 顺序 = 时间顺序**：k-bin 量化把每个时间步的每一维拆成独立 token，若 token 排列不按时间分块，`[d, d+s)` 的"执行视野"边界就切不准；务必按 `(t, dim)` 展平并显式记录 index→(timestep, dim) 映射。
- **前缀坐标一致性**：冻结的是"动作值"，若动作是相对量且换了控制周期（30 Hz→50 Hz），前缀必须重采样/换算，否则冻结段与新段尺度不一致。

## 与 Fruitsort 代码的接口约定（可直接照抄的字段）

```text
ChunkTokenBundle:
  tokens:      int16[H, A]        # 量化后的动作 token，未解掩码处 = MASK_ID
  mask:        bool[H, A]         # True=已解掩码（可执行）
  obs_ts:      float              # 观测时间戳（秒）
  d:           int                # 本次推理的离散延迟（控制步）
  s:           int                # 执行视野
  bin_edges:   float[A, 257]      # 每维量化边界，反量化用
```

- `policy_server` 只依赖 `tokens/mask/obs_ts`，不关心机器人型号 → 之后换 Franka 7 维或加第 8 维（如吸盘负压）只改 `A`。
- 反量化后再做一次**速度限幅 + 加速度限幅**，这是异步里唯一便宜的"物理兜底"。

## 对 Fruitsort 的可执行建议（传送带 / 单 Franka）

**模块划分**

1. `perception_node`：固定俯视 + 腕部相机 → 果检测/分割（苹果、草莓、梨、香蕉）→ 位姿 + 传送带速度估计（可用光流或编码器）。输出带时间戳的 `TargetState`。
2. `policy_server`：VLA（Qwen2.5-VL-3B 级）+ **离散扩散动作头**；输入当前帧 + 目标描述 + 已冻结前缀 token，输出 token 序列（部分掩码）。
3. `exec_client`：Franka 外环 30 Hz，读取 token→动作，5× 插值到 150 Hz 下发；维护 `last_chunk`，负责拼接前缀。
4. `safety_guard`：力/电流阈值、工作空间包围盒、丢帧降级（退回最近完整 chunk 或安全停）。

**落地参数（建议初值，均可先在小数据上扫）**

- 动作表示：7 维 `[Δx, Δy, Δz, rot6d(3~6), gripper]`，选 **Δ 末端位姿 + 基座系**（与 UR5e 论文一致，Franka 同样适用）；**不要**用绝对关节角，异步前缀冻结才在笛卡尔空间保持几何一致。
- 量化：**256 bins/维**；H=16，7 维 → **112 token**（比论文 160 略少，单卡 5090 更宽裕）；unmask 步数 6–8。
- 异步：`d = floor(latency / 33.3ms)`（30 Hz 外环），`s = max(2, d)`；初值 d=4、s=4。前缀取 `last_chunk[s : s+d]`。
- 早期退出条件：`[d, d+s)` 全部解掩码即停，不等整段完成；把剩余掩码率当作下一次的引导强度。
- 传送带时间预算：允许位移 `Δy_allow = v_belt × (latency + 0.5·s·Δt)`。例：v=0.15 m/s、latency=80 ms、s=4、Δt=33 ms → 约 **22 mm**；这决定抓取点应前置多少（可用"预瞄点 = 当前位姿 + v_belt·Δy_allow"作硬编码兜底，再让策略学残差）。
- 分果种策略：
  - **草莓**（软、易损、常成簇）：把 s 调小（2–3）换取更高重规划率，力控限幅 + 接近段降速；抓取窗口窄，优先保 TTFA。
  - **香蕉**（长条、姿态关键）：H 加大到 24，让"整段轨迹"更连贯；rot6d 必须完整保留，别只回归 yaw。
  - **苹果/梨**（会滚、近似球）：加"未来位姿外推"输入（把 v_belt 拼进观测），并对抓取高度做 ±5 mm 的网格搜索式数据增强。
- 训练数据：每条 demo 存 `(多相机帧, 本体状态, 动作 chunk, 时间戳)`；时间戳必须保留，后面做延迟随机化（d~U{0,10}）时要用。
- 评测：按果种分别报成功率、**平均 TTFA**、丢果率（掉出传送带）、表皮损伤率；每个配置 ≥30 trials，用 bootstrap 给 95% CI。

## 复现成本与风险

- **算力**：真机配置 3B VLM + 36 层 DiT，训练 8×RTX Pro 6000；单卡 5090 32GB 只能小 batch + LoRA/梯度检查点，或直接基于开源 π0/StarVLA 权重做离散头替换（改动集中在最后一层 logits，论文即如此）。
- **环境风险**：JAX/Flax 在 sm_120 上的 wheel 支持需先验证（Kinetix 实验是 JAX，8×RTX 6000 PRO）；真机栈是 PyTorch，无此问题。
- **依赖**：异步语义依赖"上一 chunk 尾部 = 下一 chunk 前缀"的索引对齐，一旦改控制频率或丢帧必须重算 d，否则前缀错位会直接抖。
- **未明确**：真机 Figure 6 的具体成功率数值在 pdftotext 中字体编码损坏，无法逐项引用；只能引用摘要的 +65% / +30% 与 0.7×/1.7×。
- **论文自述局限**：k-bin 量化 token 序列过长；AR-VLM 与离散头解耦，骨干不参与迭代 unmask；max-confidence 解码不会自发形成"隐式自回归"顺序（附录 B.1 图 7 显示它常把预算摊到整段，early-stop 收益被吃掉）——这条对我们很关键：**需要自己加 AR-block 式的"从前到后"解掩码顺序**。

## 原文关键片段

1. "the inter-chunk pause of synchronous executors is fatal for dynamic tasks regardless of how fast the inference is. Asynchronous execution—thinking while acting—is therefore a structural requirement"（Abstract）
2. "we observe that discrete diffusion policies, which generate actions by iteratively unmasking, are natural asynchronous executors that resolve all limitations at once: they are fine-tuning free since inpainting is their native operation"（Abstract）
3. "DiscreteRTC is simpler to implement with 0 lines of additional code to enable async inpainting, faster at inference with only ∼0.7× computation compared with generating actions from scratch, and better at execution with 65% higher success rate in real-world hockey defend task"（Abstract）
4. "with committed tokens from previous chunks, the tokens to unmask per inference are reduced, leading to lower inference cost for inpainting."（§1，贡献 (d)）
5. "the max-confidence unmasking trajectory does not exhibit this desired implicit AR-style ordering. Instead, the policy distributes its unmasking budget across the entire chunk based on per-token confidence"（§B.1，Natural Schedule Ablations）
