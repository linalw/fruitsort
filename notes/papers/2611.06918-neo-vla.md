# NEO-VLA：原生视觉-语言-动作策略

> arXiv:2611.06918 · S-Lab NTU + SenseTime + Ropedia · 2026-11
> 代码 https://github.com/EvolvingLMMs-Lab/NEO · 权重 https://huggingface.co/weepiess2383/NEO-VLA
> 数据 https://huggingface.co/datasets/weepiess2383/NEO-VLA-Action-Pretrain

## 一句话结论

去掉独立视觉编码器，让像素 patch 与文字在同一个 40 层主干里共同演化，动作专家按层读 KV。冻结主干 90.9%（Qwen3-VL-2B 79.5 / Gemma-3-4B 84.5），全参微调 95.3%。

## 方法核心

- 两级卷积 patch embedder（总 stride 32），每 32×32 一个 token，保长宽比，每视角 ≤88 token；无 ViT/VAE。
- Native 3D RoPE（t/h/w）；文本因果、视觉块内双向。
- 结构化 prefix：多视角图 + 相机内参/旋转 + 控制频率/embodiment/夹爪构型/动作坐标系 + 6 个状态 token。
- 动作：每臂 chunk ∈ R^{2×30×26}；flow matching，τ~Beta(1,1.5)，10 步 Euler，无 CFG。
- 层映射：first-28 / skip-28 / end-28 / full-40；默认 skip-28。
- 三阶段：冻结主干训专家 → 全参（混多模态理解数据，NTP loss 0.1）→ 真机微调。

## 对 Fruitsort 的可执行建议

1. **动作专家读早期层**这一结论值得在我们的 small-VLA 上扫超参。
2. **分组加权 flow loss**（EEF+夹爪 ×2）——分拣精度就在末端与夹爪。
3. **结构化 prompt 必须写控制频率与动作坐标系**，20 Hz 仿真 / 15 Hz 真机切换时不至于错。
4. **action-only 微调会让空间泛化崩掉**（C2R 10.7），必须混多模态理解数据。
5. `neo-vla-serve` 的 HTTP 策略服务接口可作为 GPU 与 Franka 控制器之间的边界（注意 260+ ms 延迟，需要异步/残差）。
6. 五条数据清洗规则（关节跳变、恒定通道、越界动作、坏 episode、相机标定一致性）可直接用于自采水果数据。

## 复现成本与风险

- 代码 Apache-2.0、权重/语料公开；但 NEO-2B 主干需单独获取，完整训练需 8 卡级预算。
- 单卡 5090 现实路径：用已发布的 LIBERO/RTW checkpoint 做真机/仿真微调，而不是从头预训练。
- LIBERO-Pro 的位置/任务扰动仅 3.0/6.3，说明空间与目标泛化仍是短板——水果换位/换筐必须自建扰动测试。
