# Reflex / ReflexBench：把"推理延迟"做进 benchmark，再用 1B 模型赌回来

> **arXiv**: `2608.14379v1` [cs.RO] · 2026-08-14
> **机构**: Shanghai Jiao Tong University（Yuxuan Chen, Wanruo Zhang, Xiao Li）
> **项目页**: <https://reflexvla.github.io/>
> **Benchmark 代码**: <https://github.com/LxRoboticsLab/ReflexBench>
> **数据集**: <https://huggingface.co/datasets/cyx337/ReflexBench_dataset>
> **ReflexVLA 代码**: "Code — After acceptance"（**尚未发布**）

## 一句话结论

这篇最值得抄的不是模型，而是**评测协议**：把"仿真步进"和"策略推理"解耦，让环境在策略算的时候继续走，并支持同步/异步两种延迟注入与可调延迟——这一条能立刻解释 Fruitsort 仿真里那些"看上去 90%、真机 0%"的差距。模型侧结论更像经验法则：**chunk 大 + 执行步数少 + 高频异步 + CUDA Graph**，比加参数更救命（1B 模型 30.3% → 50.4%，延迟 125→65 ms）。

## 要解决的问题

- 现有 VLA benchmark 主要测静态泛化，**忽略"物体在推理期间还在动"**；更糟的是大多数仿真 benchmark 在推理时**暂停环境**，等于凭空消掉了感知-执行延迟，指标虚高。
- 已有工作分成两半：动态 benchmark（只评测，不研究"预测+效率"如何一起做）与高效 VLA（只压延迟，不解决"未来感知"）。**"既会预判又跑得快"没有被统一研究**。
- 作者把问题拆成三块：① 需要未来感知；② 需要历史帧（单帧看不出运动）；③ 需要低延迟。

## 方法核心（含关键公式/伪代码）

### 1. ReflexBench：延迟感知评测（最有价值的部分）

**六个任务**（全部仿真，单一策略多任务训练）：

| 任务 | 动态性来源 |
| --- | --- |
| Conveyor Belt Pick-and-Place | 方块 + 干扰物沿传送带移动，要抓方块放进旁边料框 |
| Ball Catching | 来球位置快速变化 |
| Whack-a-Mole | 目标随机位置**短时出现**，没打到就消失 |
| Rolling Ball Interception | 球沿斜面滚下，要在坡边截住 |
| Ball Throwing | 把球投进料框 |
| Rotating Peg Insertion | 把销插入**连续旋转**的孔 |

**延迟注入机制**（两种部署范式）：

- **同步**：暂停仿真取观测 → 推理 → 恢复 → **机器人空等 latency** → 执行动作块。
- **异步**：策略在机器人执行**上一轮**动作块期间推理，新块下一控制周期才生效。
- **延迟可手动指定**，不改策略也不改硬件，从而做受控消融。
- **真实延迟换算**：先测真机推理延迟 `t_real`，再按 **RTF = t_sim / t_wall** 折算成仿真延迟注入。
  `Δt_sim = t_real × RTF`
- 关键实现要求：**仿真以真实时间步进（而非"推理时冻结"）**，控制环与物理环分离。

### 2. ReflexVLA：三件套（1B）

基座：**VLA-Adapter**（DINOv2 + SigLIP 融合 ViT，224×224；语言主干 Qwen2.5-0.5B；可学习 action query + 连续回归头输出动作块）。

**(a) 潜空间未来预测（只加训练损失，不加推理成本）**

- 未来观测用**冻结的 DINOv3** 编码：`y_{t+i} = φ_DINOv3(o_{t+i}) ∈ R^1024`。
- 在输入序列尾部追加 **H 个可学习 future token，H = 动作块长度**（一一对应一个未来控制步）——这是设计精髓：**预测时域 = 动作时域**。
- 投影：`ŷ_{t+i} = f_pred(h_future_i)`。
- **掩码余弦损失**：`L_future = Σ_i m_i [1 − cos(ŷ_{t+i}, y_{t+i})] / Σ_i m_i`，`m_i` 标记该未来帧是否有效。
- 总损失：`L = L_act + λ_future · L_future`，**λ_future = 0.05**。

**(b) 多帧时序融合（在视觉主干内部做，不吃 LLM token）**

- 取**中间层**特征 `X_mid ∈ R^{B×V×T×P×D}`（不是最后一层）。
- 对每个视角 v、每个 patch p，把 T 帧同位置特征当一条"时间轨迹"：`z_{v,p,1:T} = Down(LN(x_mid) ) + e_{1:T}`（时间位置编码 + 降维）。
- **因果时序注意力**：`Δx_{v,p,t} = Up(MHA_causal(z_{v,p,1:T})_T)`，因果掩码防止看未来帧，与在线部署一致。
- 融合进当前帧：`x̃ = x_final_{v,p,t} + Δx_{v,p,t}`；**送进 LLM 的视觉 token 数与单帧完全相同**（避免 V·T·P 的二次复杂度）。

**(c) 推理延迟优化（系统级，不改模型）**

- **批量化视觉编码**：V×T 张图一次前向，而不是 V×T 次。
- **CUDA Graph 捕获整条推理链**：`â_{t:t+H−1} = G(x_text, x_vision, x_state)`，新观测只做 buffer 拷贝 + graph replay。
- 效果：**125.1 ms → 65.0 ms**，且成功率还涨（71.7 → 73.8）。

### 3. 数据采集（对动态任务是硬约束）

静态任务可以脚本/遥操作，动态任务不行。作者用**分层规划器**：把任务拆成带子目标的阶段（如旋转插销：预对准 → 目标跟踪 → 定时插入）；**规划器用实时位置+速度预测未来轨迹**，朝预测态规划；规划搞不定的交互动力学，再训**任务专用 RL 策略**产演示。→ 6 任务 × **200 条** = 1200 条。

### 延迟/分块的经验规律（Fig. 4/5，SmolVLA 上的系统性扫描）★

- **低频时异步更差**：5 Hz 时 async 只有 8.6%（传送带）/ 12%（滚球），sync 有 16% / 22%——因为观测-动作错配太大。**频率越高异步才越赚**（30 Hz：async 31.3 vs sync 22.6）。
- **chunk 大 + 执行步数(horizon)少** 在 30 Hz 异步下普遍最好（Fig. 5 的二维矩阵中，大 chunk 列 × horizon=1 行整体最高）。⚠️ 该矩阵在 pdftotext 里单元格顺序被打乱，**具体数值必须回 PDF 原图核对**，本笔记不引用其逐格数字。
- 含义：**"多预测、少执行、勤重推"** 优于 "少预测、长执行"。

## 对 Fruitsort 的可执行建议（传送带动态分拣：苹果/草莓/香蕉/梨，单 Franka 臂）

### A. 立刻照抄：延迟感知评测（最高优先级）

ManiSkill3 默认在策略推理时可能"世界不动"，这会让你的传送带任务乐观 20–40 点。做法：

1. **物理环与策略环分线程**：物理按 30 Hz 固定步长推进（不看策略脸色），策略在另一线程/进程推理。
2. **延迟注入开关**：`--latency-ms 0/40/80/120/160`，同步模式下推理期间让机器人"保持上一指令"（等价于空等）；异步模式下允许"上一块还在执行时推新块"。
3. **真机延迟折算法**：本机测出策略 `t_real`，用 `RTF = t_sim/t_wall` 折算（5090 上 RTF 会随场景复杂度变化，必须每个场景单独测）。
4. **必报三个数**：成功率、**推理延迟分位（p50/p95）**、**动作块执行占比**。Fruitsort 的 `runs/<id>/metrics.json` 建议加 `p50_latency_ms / p95_latency_ms / chunk / horizon / async`。

### B. 分块策略参数（直接可试的起点）

- **chunk = 8–16，action horizon = 1–2，30 Hz 异步**（论文最优区）。含义：每 33–66 ms 重推一次，块里只执行前 1–2 个动作。
- 传送带速度越高，horizon 越应取 1（Fruitsort 若带速 0.2–0.3 m/s，苹果直径 7 cm，66 ms 内移动 1.3–2 cm——horizon=2 的位置误差已接近抓取容差，建议 **horizon=1**）。
- 对比自测：`sync vs async × {5,10,20,30} Hz × chunk {2,4,8,16} × horizon {1,2,4,8}` 的小网格（论文就是 4×4 网格，很便宜），别拍脑袋。

### C. 训练侧：加"未来 token"（零推理成本，强烈建议）

- 未来目标用**冻结的 DINOv3**（或本机已有的 DINOv2/SigLIP），**绝不可训练**——可训练目标直接崩到 4.9%，这是本文最反直觉也最可复现的一条。
- 未来 token 数 = chunk 长度（例如 chunk=8 就 8 个 future token），**一步一个 token**，序列增长可忽略。
- `λ_future = 0.05` 起步；掩码 `m_i` 处理 episode 末尾不足 H 帧的样本。
- 语义：等价于在 latent 空间做"未来 N 帧的 1-token 摘要"，比 AHEAD 的整网格 patch 预测便宜得多，**适合先做**。

### D. 时序融合：中间层 + 因果注意力，token 数不变

- 只取 **2 帧**（论文的 T=2），在 ViT **中间层**做 per-patch 因果时序注意力，再把 `Δx` 残差加回**最后一层**当前帧特征。
- 好处：LLM 侧 token 数不变，Qwen/VLM 的 KV 长度不涨，延迟可控。
- Fruitsort 若用多相机（第三人称 + 腕部），务必沿用"先 batch 所有视角×帧，再一次视觉前向"，否则 V×T 次前向会把延迟吃光。

### E. 系统级（5090 上最容易拿到的免费加速）

- **CUDA Graph** 捕获"视觉编码 → 时序融合 → 投影 → LLM → 动作头"整链，输入 buffer 固定形状（batch、视角数、token 数都要 pad 到固定值）。**125→65 ms 是纯工程收益，且成功率不降。**
- 注意：动态 shape（不同 padding 的指令长度）会打断 graph，需固定长度 + padding。

### F. 任务设计：把"传送带 + 干扰物"做成标准关卡

- 仿 ReflexBench 的 Conveyor：**传送带 + 目标果 + 干扰物**（相似颜色的小果/叶子），必须抓指定那颗 → 顺带测语言 grounding（论文的传送带任务 73.8% 说明这项还没被解决）。
- 加一个 **Whack-a-Mole 类**任务（果子在带上一亮一暗/间歇出现）→ 专门测"时机"而非"追踪"，这是 Fruitsort 的节拍考核。
- 加 **Rotating Peg** 类（把草莓放进一个转动的托盘格口）→ 模拟"动态放置"而非"动态抓取"，这是分拣线的另一半（论文此项只有 12.4%，是空白区）。

## 复现成本与风险

- **代码不可得**：ReflexVLA 标注 "after acceptance"，目前只有 ReflexBench 环境与数据集。模型侧需自己按 VLA-Adapter + 三个改动重写，工作量 ≈ 2–3 周（VLA-Adapter 已开源）。
- **算力**：1B 模型，单卡 5090 可训（论文未报训练卡时，但演示量仅 1200 条，规模小）；真正的成本在**数据**——6 个动态任务的规划器/RL 演示生成。
- **数字偏低是重要信号**：平均 50.4%，接球 7.3%、旋转插销 12.4%。说明"纯端到端 VLA + 小模型"在**弹道类/高精度动态**任务上仍基本不可用；Fruitsort 若做到 0.3 m/s 传送带，应预期落在"传送带 60–80%"区间，不要照抄平均 50% 当目标。
- **消融里的坑**：可训练未来目标 → 4.9%，说明辅助损失的目标分布很脆；同时 `λ_future` 只试了 0.05，敏感性未知。
- **RTF 折算的隐患**：RTF 随场景负载变化，若用固定 RTF 会高估/低估延迟；且仿真 30 Hz 与真机控制器的抖动未被建模。
- **没覆盖**：腕部相机（本文用多视角但未说是否含腕部）、力控、易损物体、多臂协同。

## 原文关键片段

1. "Unlike existing simulation benchmarks that pause the environment during policy inference, ReflexBench decouples simulation from robot control, allowing environmental dynamics to evolve independently of policy computation and enabling more realistic evaluation."
2. "Given a measured policy inference latency in the real world, we compute the equivalent delay in simulation according to the simulator's RTF and inject the corresponding latency into the evaluation process."
3. "The prediction horizon H is chosen to be identical to the chunk size used by action prediction, such that each future token corresponds to one future control step within the predicted action chunk."
4. "Directly training the model to predict future visual representations with a trainable visual target results in a substantial performance degradation … using features extracted from a frozen DINOv3 encoder provides a stable semantic prediction target and improves the success rate from 36.8% to 62.8%."
5. "Larger chunk sizes with shorter action horizons under asynchronous inference generally achieve better performance … The improved success rate demonstrates that reducing deployment latency is particularly important for reaction-critical manipulation tasks."

## 存疑 / 未说清

- 六个任务的**成功判据**没有逐条给出（只有任务描述），复现时无法严格对齐。
- 延迟注入的**具体数值**（默认 latency ms、控制频率是否 30 Hz）正文只在实验设置里给 30 Hz，其余含糊。
- 传送带速度、球速等**物理参数未报告** → 无法判断难度是否等价于 Fruitsort。
- "single policy on the same dataset" 但 6 任务差异极大（打地鼠 100% vs 插销 12.4%），是否共享视觉/动作空间未说明。
- 真机 CatchBalls 只有 6.7/10，与仿真 7.3% 无法互相印证（口径不同）。
